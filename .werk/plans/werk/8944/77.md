## What to build

Each project gets its pipeline log: one append-only file in werk's store, one event per line, tracked by git like the decision log. A pure fold reads it; nothing in v0 builds a report over it. Detail files sit beside it and are not tracked: one file per agent session holding its full stream, and one folder per plan holding its copy.

A plan is the first writer. When it starts, it appends a plan start event that lists every scope card with its tier and the log position of that card's last change, plus the size of the input: the card count per tier and the length in characters of the scope text in the prompt. Each writer step appends a step start, and on exit a step end with wall time, cost and the token breakdown (input, output, cache read, cache write), the result, and the name of its session file. When the plan ends, it copies the spec, every ticket it wrote or changed, and each writer's answer records into a folder of its own, lists the ids of the open tickets it kept unchanged, and appends a plan end event that names that folder and the result. A copy is a record only: no plan or build reads it.

The plan's board log events stay as they are. The pipeline log module and the session file writer are shared, so the builder loop, the merge loop and the held-out run later append to the same log through them.

## Acceptance criteria

- [ ] A scripted plan appends a start event whose scope list names each card with tier and log position, and the counts per tier.
- [ ] Each writer step has a start and an end with cost, tokens, wall time, result and a session file that exists beside the log.
- [ ] After a second plan of the same subtree, its copy folder holds only the changed spec and tickets and lists the kept ticket ids.
- [ ] The copy folder holds the answer records each writer returned.
- [ ] A comparison of two plan start events shows which scope card's log position changed between them.
- [ ] The session files and copy folders are ignored by git; the pipeline log is not.
- [ ] The pipeline log fold is a pure module that passes the coverage gate.
