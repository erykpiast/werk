## What to build

werk starts each pipeline agent with a role in its environment. This ticket makes the same role pick the agent's model. One small pure table maps each role to a pinned model id and an optional advisor: the spec writer, the ticket writer and the grader run on Opus; the builder runs on Sonnet with Opus as advisor; every reviewer role, the held-out step author, the held-out binder and the overseer classifiers run on Sonnet. Model ids are exact pinned ids, never the short aliases. A role that is not in the table, such as the chat agent, gets no entry: the chat agent keeps the model of the chat selector.

The plan's two writers already launch with their roles; this ticket makes them launch with the model and advisor flags from the table. Later tickets that start a builder, a grader, a reviewer, a step author, a binder or a classifier read the same table, so no launch names a model of its own. A role name that is not in the table and is not the chat role is a programming error that the table reports, not a silent default.

## Acceptance criteria

- [ ] With a scripted plan, the launch record of the spec writer and of the ticket writer shows the pinned Opus id and no advisor.
- [ ] The table returns the pinned Sonnet id with the pinned Opus id as advisor for the builder role.
- [ ] Every reviewer role of the form reviewer-<area> resolves to the pinned Sonnet id with no advisor.
- [ ] No entry of the table uses a model alias.
- [ ] The chat agent's launch still uses the model chosen in the chat selector.
- [ ] The table is a pure module on the pure list and passes the coverage gate.
