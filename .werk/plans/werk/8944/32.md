## What to build

At the end of its work, each pass after a red one names one cause of the last failure with a sentence of reason: builder error, test is wrong, spec gap, false finding, or conflict for a merge fail. The cause is stored on that pass in the pipeline log and attributed to the one before; a cause the check run set (flaky, check infrastructure) comes first. A fail at the cap keeps an unknown cause.

When the cause is a spec gap, or the grader or reviewers raise findings in the same area in two passes in a row, the next pass is a decision pass. The builder states the question, picks the answer that is easiest to undo and safest when wrong, and proposes it as a ghost card with the question as title, the answer, the rejected options and its depends_on, with who you. From then on the ticket cites the proposal and the grader judges against it as if it were decided. A pass that ends on a spec gap does not count against the retry cap; later failed passes count as usual, so a ticket gets one free pass per open question. The build's end lists every proposal made by its builders.

## Acceptance criteria

- [ ] A pass that names a spec gap leaves the counted passes unchanged, and the next pass's prompt asks for a decision.
- [ ] The decision pass's proposed ghost is cited by the ticket in the following grade.
- [ ] A later builder-error fail counts against the cap.
- [ ] Two passes in a row with grader gaps in the same area trigger a decision pass.
- [ ] A spec gap on the last counted pass still gets its decision pass.
- [ ] Each named cause is in the pipeline log on the pass that named it.
