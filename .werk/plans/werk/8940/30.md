## What to build

`werk build <ticket-id>` builds one ready ticket in the target repository. It makes a worktree branched from the main line's tip and opens a card obligation in the decision log. Each pass starts a fresh agent with the role builder whose prompt starts with `/implement` and holds the ticket, the spec lines of its stories, its cited cards with their rejected options and reasons, its checks, the obligation, the index of decided cards with a rule to search the map before deciding what no cited card gives, and the last failure cut to about 4000 characters; the first pass is told nothing is done yet. After the agent exits the loop commits what it left as pass n.

The loop then runs the ticket's checks in order, each a make target whose exit code is the verdict, stopping at the first red one. A red check runs once more on the same commit: green on the rerun records the cause flaky and the check counts as green; a crash, timeout or missing tool before the code ran records check infrastructure and is not rerun. A red pass feeds the next pass. The retry cap (default 5) counts passes across all builds of the ticket. Every time limit is a parameter, clamped by the shared budget.

A green build moves the ticket to merging and records its branch; a build red at the cap moves it back to ready with the reason. Board events record build started (naming the process and the session log), each pass, and build ended. Each agent's stream goes to its own session log beside the pipeline log, which is not tracked by git. The pipeline log, append-only and tracked, gets each step's start and end with wall time, cost, tokens, result, and for a red step its gate and cause, so effort per ticket can later be folded from it.

`werk followed <obligation> --cards a,b` closes an obligation with "no new decision" and the decided cards the pass followed; an unknown, closed, ghost or undecided id is refused with exit 1.

## Acceptance criteria

- [ ] A fake builder whose edit makes `make test` pass ends green in one pass and the ticket moves to merging with its branch.
- [ ] A fake whose checks stay red stops at the cap and the ticket goes back to ready with the reason.
- [ ] A check that fails then passes on rerun is recorded as flaky and does not cost a pass.
- [ ] The second pass's prompt holds the first pass's failure, and no conversation from it.
- [ ] The pipeline log holds a start and an end for every pass and check, with cost on agent steps.
- [ ] `werk followed` closes an open obligation once, and refuses a second time.
