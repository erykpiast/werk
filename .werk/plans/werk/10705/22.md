## What to build

werk ships one instruction text for agents and the definitions of the subagents it names. The text holds the map rules in full, cites no card of werk's own map, uses made-up ids in its examples, and names every command by the path werk runs from. It states the card wording rules and that a chat reply names a map operation, not a command line.

One pure module builds the launch options of any agent from its role: the role name in its environment, the model of that role (Opus for the spec writer, ticket writer and grader; Sonnet with Opus as advisor for the builder; Sonnet for reviewers, held-out agents and classifiers; the chat's own setting otherwise), and for every role that can write the map the instruction text and the subagents appended after the agent's own system prompt, together with the titles of the project's build-rule cards. A sample or diagram role gets no text. When the project is werk's own checkout, the text is not added twice.

werk reads its own files, the instruction text and the subagents included, through a list of its own files that the build writes, never by listing a folder.

## Acceptance criteria

- [ ] The launch options for the builder carry the builder role, the Sonnet model with the Opus advisor, and the appended text.
- [ ] The launch options never replace the agent's own system prompt.
- [ ] A role with no map writes gets no instruction text.
- [ ] The launch options include the titles of the build-rule cards of the project.
- [ ] The text contains no id of a card in werk's own map, and its commands name the running werk.
- [ ] The launch options module passes the coverage gate.
