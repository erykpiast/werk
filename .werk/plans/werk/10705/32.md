## What to build

The target verb sets the project's target repository, prints it with no argument, and refuses a path that is not a directory, has no main line, or lies inside or holds werk's store. The build commands of later tickets read this target, and with none set they exit 1 and name the target verb.

The plan verb takes a subtree id. It collects the scope: the subtree, each card a subtree card links by depends_on or by a #id in its text (first tier), and from there every decided card they depend on with its subtree (second tier), never walking up to a parent and stopping at open, proto, stale or postponed cards. An open or proto card in the first tier stops the plan before any agent call.

One pipeline agent runner starts every pipeline agent as a child with the launch options of its role, a session log of its stream, a wall-clock limit, and start and end events in the pipeline log. The plan runs the spec writer, then the ticket writer, each with read and write tools only. Each writer returns its new answers as records with a slug, title, why and body; the plan proposes each as a ghost under the subtree root with who me, and a record it cannot propose fails the plan. The spec and tickets go to werk's store for the project, never to the target.

The plan then runs the ticket-check operation. A ticket that fails its own checks gets no planned event. Every other ticket is planned; a failed set check is reported, puts the tickets it names in blocked with the reason, and the plan exits 1. The board log gets plan started, one plan step per writer and plan ended.

## Acceptance criteria

- [ ] The target verb prints the path it set, and refuses a path inside werk's store.
- [ ] A plan over a subtree whose first tier holds an open card stops before any agent launch.
- [ ] With scripted writers, the plan writes the spec and tickets to werk's store and plans each valid ticket in ready or blocked.
- [ ] A writer's answer record becomes a ghost card under the subtree root.
- [ ] The launch records show the spec and ticket writer roles on the Opus model.
- [ ] A ticket with a file path is not planned, and the plan exits 1.
