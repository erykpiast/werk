## What to build

`werk serve [--port]` starts one server process. The server holds one context per project (map, and later conversations, agents and builds); this ticket opens one context for the project it starts in, so a later project list adds contexts without reshaping the server. The project's store location can be set through the environment, which tests use.

Each project store has one lock file, taken by an exclusive create that fails when the file exists. A start that loses reads the lock: a dead pid is stale and is replaced; a live pid makes the start poll until the wait ends, then refuse with a message naming the pid and port; a lock that does not parse counts as held during the wait and stale after it. The lock is released on exit and on interrupt.

The server makes a random token at start and puts it in the page it serves. Every request that writes or starts anything must carry it, and every request whose Host is not a loopback name is refused. The token never goes into a log or into an agent's environment. Read requests need no token.

The map API is card-scoped: one read returns one card with its body, why, status, marks, rollup and its neighbours' ids and titles; one read returns the shape of the whole map (ids, kinds, statuses, edges, rollups) with no bodies. The server watches each project's log directory and starts the watch before it accepts connections. When the log grows, it sends a bare changed signal with no data on the live channel to every open page; the page then reads again.

## Acceptance criteria

- [ ] Two `werk serve` starts on one store at the same moment: exactly one runs, the other refuses after the wait.
- [ ] A stale lock from a killed server is replaced and the new server starts.
- [ ] A write request without the token, or with a non-loopback Host, is refused; a read request without the token succeeds.
- [ ] The card read returns one card with neighbour titles; the shape read holds no body text.
- [ ] A command-line add while the server runs sends one changed signal with no payload to each connected client.
- [ ] A write made before the server started shows in the first read after connect.
