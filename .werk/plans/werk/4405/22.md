## What to build

Claude Code's own permission engine in auto mode decides which calls are safe; werk keeps no classifier of its own. A call the engine cannot resolve arrives as a control request on the child's output; the server pushes it to the conversation's pane and the child stays blocked. The ask bar above the composer names the tool, shows the call as a code block and the CLI's reason as given, and offers Allow once and Deny, plus Always allow only when the CLI attached a widening suggestion, with that rule shown on the button. One click disables every button. Cmd+Enter answers the first open ask with allow and Escape with deny; plain Enter in the composer still sends and Cmd+Enter never sends. The answer goes back on the child's input with the same request id.

Always allow stores the CLI's own suggestion per conversation and applies it to the live process at once and to every relaunch as allowed tools and directories. Every answered ask is appended to an ask log with the tool, input, reason, decision and rules added.

An agent's question tool call shows as a form: each question with lettered options and their descriptions, a free-text field, Submit answer and Decline. The answer reaches the model as one line per question, `For "<question>": <labels>`, sent as the reason of a refusal that the log does not mark as a failure. Half-filled selections survive a re-render.

## Acceptance criteria

- [ ] A scripted ask shows the bar with the call and reason, and Allow lets the fake's turn finish.
- [ ] An ask with no suggestion shows two buttons; one with a suggestion shows Always allow with the rule.
- [ ] Always allow applies to the next identical call in the same process and after a restart.
- [ ] A second click after the first answer sends nothing.
- [ ] A question form submits the picked labels in the fixed line format.
- [ ] Each answered ask appears in the ask log.
