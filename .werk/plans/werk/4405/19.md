## What to build

werk keeps one agent instruction text, written for any project: keep the map current every turn, every add is a ghost and only the person accepts, record depends_on and rejected options when a card is made, the wording rules for titles, whys and bodies, tag who decides, name a map operation rather than a command line in a chat reply, and classify a module before deciding its tests. The text writes out every rule it uses and cites no card id of werk's own map. It names werk's command line by the path werk runs from.

A pure prompt builder appends that text after the agent's own system prompt and never replaces it. It adds the text for the chat agent, each build pass and the plan writers; a sample agent and a model call with no tools do not get it. When the project is werk's own checkout, whose AGENTS.md already includes the text, it is not added twice. The builder also adds a list of the titles of every card under the build-rules card #how; with no children, no list.

werk ships the definitions of the subagents the text names (the one that classifies a module for testing, and the one that builds the options of a fork) beside the instruction text, and passes them to every agent that gets the text, with werk's path filled in. werk's own repository links its Claude Code subagent folder to these files, and a check fails when a shipped subagent has no link or a same-named file is not a link. AGENTS.md includes the shared text.

## Acceptance criteria

- [ ] The prompt for a build pass is the base prompt followed by the werk text and the titles of the #how children.
- [ ] A sample agent's prompt holds no werk text.
- [ ] In werk's own checkout the text is not added a second time.
- [ ] The instruction text and subagent definitions contain no card id from werk's own map.
- [ ] The link check fails when a shipped subagent's link in the repository is replaced by a copy.
- [ ] The prompt builder passes the coverage gate.
