## What to build

Header row 1 holds the breadcrumbs: the path from Home to the open card, separated by `›`, each ancestor a button, the open card bold. They stay one line high: the last two segments always show, a third when the left pane is at least 700px wide, a `…` for the rest, and a hover overlay shows the full path. Header row 2 has the counts on the left (total, then dots for open, proto, decided, then rings for unchallenged, stale, paused; zeros left out; each with a hover title) for the open card's subtree, and on the right the view tabs (Map, Board; the active one highlighted; the view remembered on reload) and the search box.

The search box lists up to twelve nodes whose id, title, reason or finding holds the typed text; a query starting with # matches ids only, exact id first, then prefix, then contains. Each row shows a status-coloured dot (red when stale, split amber and grey when postponed, a kind colour for options, sources and excerpts), the title and the id. Arrows move the selection, Enter opens it in the map, Escape clears.

The home view is the first screen: two equal columns, the root of the requirements on the left and the build-rules card #how on the right, each with title, why, counts and children. With no #how card, the right column shows an empty build-rules card.

## Acceptance criteria

- [ ] Opening a card four levels deep shows a one-line path with `…`, and hovering shows the full path.
- [ ] The header counts change when a different card opens, and add up across the status dots.
- [ ] Typing `#werk` lists the exact id first; Enter opens it and clears the box.
- [ ] A stale card's search row has a red dot.
- [ ] The Board tab opens `/board`, and the Map tab returns to the last open card.
- [ ] The home view shows #root and #how side by side.
