Scenario: A first plan of a subtree records its scope, its steps and its copy
Given a project with a decided subtree of three cards, two at one tier and one at another
And the project has no pipeline log yet
When a person runs a plan over that subtree and the plan finishes
Then the project's pipeline log has a plan start line that lists each of the three cards with its tier and the log position of its last change
And the plan start line shows the card count per tier and the length in characters of the scope text in the prompt
And the log has a step start and a step end for the spec writer and for the ticket writer
And each step end shows the wall time, the cost, the input, output, cache read and cache write tokens, the result and the name of a session file
And each named session file exists beside the log and holds the full stream of that session
And the log has a plan end line that names the plan's copy folder and the result

Scenario: The copy folder holds the spec, the tickets and the answer records
Given a plan of a decided subtree whose spec writer and ticket writer each return answer records
When the plan finishes
Then the plan's copy folder holds the spec the plan wrote
And it holds every ticket the plan wrote
And it holds the answer records that each writer returned
And the plan end line names that folder
And the board still shows the same events for the plan as before, with the tickets in their columns and the answers as ghost cards under the subtree root

Scenario: A second plan of the same subtree copies only what changed
Given a first plan of a subtree has finished and left three tickets open
And a person has changed one decided card in that subtree since then
When a person runs a second plan of the same subtree and it finishes
Then the second plan's copy folder holds only the spec and the tickets that the plan wrote or changed
And the second plan's copy folder lists the ids of the open tickets it kept unchanged
And the first plan's copy folder is still there and still has its own files
And the two plan start lines show that the log position of the changed card differs between them
And the log positions of the other scope cards are the same in both lines

Scenario: Detail files stay out of git and the pipeline log is tracked
Given a project where a plan has finished and has written the pipeline log, session files and a copy folder
When a person looks at the project's git status
Then the pipeline log shows as a file that git tracks or can add
And no session file shows as addable
And no plan copy folder shows as addable
And the person can commit the pipeline log and the commit holds the plan start, step and plan end lines

Scenario: A failed plan step still leaves a complete record
Given a plan whose ticket writer exits with an error
When a person runs the plan and it ends with an error
Then the log has a step start and a step end for the failed step with its result and its session file
And the session file exists beside the log
And the log has a plan end line with the failed result that names the copy folder
And the copy folder holds the spec and the answer records that the plan wrote before the failure
