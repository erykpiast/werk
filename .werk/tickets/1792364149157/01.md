## What to build

A new, empty werk repository that starts a server and shows a page. Bun runs the server TypeScript directly under hot reload. Vite transforms a React client inside the server process. Nothing is ported from the prototype.

The server keeps a guard on the global object. A hot reload of any server module reuses the live server and the live objects pinned on the global object. It does not start a second server or a second agent. A long-running child process that the server holds stays alive through an edit of a server module.

The agent can see the result of what it builds. One command runs the unit tests for the server code and the React components. One command runs the same tests with coverage and then a 90% gate over an explicit list of pure files. One command runs browser tests through the Playwright test runner against the real server, booted on a copy of a fixture project, with a scripted fake `claude` binary first on the PATH. Each browser test saves a screenshot as evidence and asserts on structure.

## Acceptance criteria

- [ ] The repository is new. It holds no code copied from the prototype.
- [ ] The dev start command runs the server under Bun hot reload, and the page loads a React view transformed by Vite.
- [ ] An edit to a server module while the server holds a live child process keeps the same process id for the server and for the child. The server logs that it reuses the live server.
- [ ] A new connection to the live channel after a hot reload sees the same server state as before the edit.
- [ ] The unit test command runs and passes with at least one server test and one React component test.
- [ ] The coverage command fails when a file on the pure-file list is under 90% line coverage, and passes when it is at or above 90%.
- [ ] The browser test command boots the real server on a copy of a fixture project, with the fake `claude` first on the PATH, and saves one screenshot per test.
- [ ] No test reaches a real agent.
