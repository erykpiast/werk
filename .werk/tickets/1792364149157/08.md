## What to build

The Markdown renderer of the client turns a card reference into a link to that card's route on the map. It applies in the card body, the why line, the finding line, and the notes thread. It does not apply in the card summary of a grid tile, because the tile is a button.

Only an id the map knows becomes a link. With a `#`, any known id links. Without a `#`, an id links only if it has a hyphen or a colon. A code span links only when it holds nothing but an id, with or without the `#`. Fenced blocks, headings, URL fragments, and code spans with more than an id stay as they are. Bold and italic markers inside a code span stay literal.

Fenced code renders in a box, with syntax highlighting for json, js, ts, and bash, and with horizontal scroll. The renderer does not reformat the code.

## Acceptance criteria

- [ ] `#known-id` and `known-id` in a body render as links. `#unknown-id` and a bare single word stay plain text.
- [ ] A code span with only an id links. A code span with a command and an id stays code.
- [ ] A fenced block, a `# heading`, and a URL with a `#fragment` are not changed by the link rule.
- [ ] A grid tile summary contains no link element.
- [ ] A click on a rendered link opens that card on the map.
- [ ] A fenced block shows boxed, highlighted, and scrolls sideways. Its indentation is kept as written.
- [ ] The link rule and the renderer have unit tests and are on the pure-file list of the coverage gate.
