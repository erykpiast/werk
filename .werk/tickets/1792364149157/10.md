## What to build

A person starts a second conversation while the first one runs a turn. By default the new conversation forks the parent session with the fork-session option, so it shares the parent's cached prefix. A second, explicit control starts an empty conversation instead.

Each conversation stores its session id and its home card: the card open when it started. The home card names the tab and seeds the first turn. It is not a fence: the conversation may go anywhere on the map.

An agent in one tab can read what a sibling conversation said, on demand, from its session log. werk gives it the exact list of sibling conversations and their home cards. No tab gets a push of what changed since its fork. Before an agent writes a card, it reads the card from the map.

The tab strip is the last row of the pane. Tabs are flush to the pane edges and look like real tabs: the active chip joins the area above it. Each chip shows the home card id. Cmd+1 to Cmd+5 select a tab by position, and Cmd+[ / Cmd+] step between tabs.

## Acceptance criteria

- [ ] A fork starts a child with the parent's session id and the fork-session option. The parent session file gains no turn.
- [ ] The empty-start control starts a child with no parent session.
- [ ] Two conversations run turns at the same time. Each reply streams to its own tab.
- [ ] Each chip shows the home card id, and the first turn of a new conversation names its home card.
- [ ] An agent can list sibling conversations with their home cards and read one sibling's session log.
- [ ] The tab strip is the last row of the pane, with no horizontal padding.
- [ ] Cmd+1 to Cmd+5 and Cmd+[ / Cmd+] switch the active tab.
