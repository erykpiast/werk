## What to build

A plan command runs over one decided subtree and the cards it links one hop out. An agent writes one spec: the problem, the solution, a numbered list of user stories, the implementation and testing decisions, and what is out of scope. A second agent splits the spec into tickets. Each ticket has a title, what to build, acceptance criteria, stories, cites, blocked_by, and checks, and names no file paths.

blocked_by is derived from the depends_on edges between the cited cards. Every spec story is delivered by at least one ticket, and every card of the subtree is cited by at least one ticket. The program runs these set checks and the per-ticket checks on the files.

The spec and ticket writers return each answer that no card gives as data. The program proposes each one as a ghost card under the subtree, so a person can see it and reopen it. The tickets enter the board state: a ticket with unmet blocked_by is blocked, the rest are ready.

## Acceptance criteria

- [ ] A plan run with the fake agents writes one spec with numbered stories and one file per ticket in the required shape.
- [ ] A ticket that names a file path, or lacks a field, fails the per-ticket check.
- [ ] A ticket set that leaves a story or a subtree card uncovered fails the set check, and the failure names the story or the card.
- [ ] A blocked_by that does not follow the depends_on edges between the cited cards fails the set check.
- [ ] Each decision the writers return appears in the map as a ghost under the subtree.
- [ ] After the plan, the board state holds each ticket in blocked or ready by its blocked_by.
