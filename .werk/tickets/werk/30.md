## What to build

The ticket-check verb reads every ticket file in a folder, the decided cards under a root card, and the story numbers under the spec's User stories heading. It runs eight checks on each ticket alone: title, shape (five header lines and three section headings in order), size of at most 4000 characters, a non-empty What to build, at least one acceptance bullet, no file paths, every Checks bullet a make target, and a touches line with at least one name that reads as no path.

It then runs three checks on the set of tickets that passed their own checks: every decided, accepted card under the root is cited; every story is delivered and no unknown story is named; every blocker is in the set and the blocked_by graph has no cycle. A blocked_by failure names only the tickets that must not start.

It prints one line per failure as ticket, check, field, message, with "ticket set" for a failure no ticket owns, then a count line. It exits 0 when nothing fails, 1 when a check fails, and 2 for a malformed call.

## Acceptance criteria

- [ ] A folder of correct hand-written tickets exits 0.
- [ ] A ticket with a path in its body fails no-file-paths, and the line names the path and its line number.
- [ ] A ticket missing its touches line fails shape and names the field.
- [ ] An uncited decided card fails on the ticket-set line; a ghost decided card does not count.
- [ ] A cycle in blocked_by names the tickets on the cycle only.
- [ ] A spec with no User stories heading exits 2.
- [ ] The ticket checks pass the coverage gate.
