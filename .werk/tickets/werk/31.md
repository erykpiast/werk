## What to build

Each project has one append-only pipeline log. A writer appends a start and an end event for every plan step, builder pass, check, grader run, reviewer run, merge and held-out run. An end event carries the wall time, the cost and the token breakdown, the result, and for a red step its gate and cause. Agent transcripts and full check output are files beside the log, named by the step's end event and ignored by git; the log itself is committed.

A pure fold reads the log for what the loop needs: the passes of a build, which failed passes count against the cap, and the last failure with its cause. The server sends a bare measure signal on the live channel when the pipeline log grows. v0 builds no report, panel or trend view over the log.

## Acceptance criteria

- [ ] Writing a pass start, a red check end and a pass end folds into one red pass with its gate and cause.
- [ ] A check end names the file that holds its full output, and that file is ignored by git.
- [ ] A pass whose cause is spec gap or conflict does not count toward the cap in the fold.
- [ ] Appending to the pipeline log sends a measure signal and no map signal.
- [ ] The pipeline log fold passes the coverage gate.
