## What to build

Before the first unit test, the test run removes every environment variable that points at a real project and puts the fake agent first in the program search list. It also makes process spawn, program lookup and the shell default to that cleaned environment, so a test that starts a process with no environment of its own still finds the fake.

The project harness gives a test a fresh directory with a git repository and an empty map, plus a fresh target repository when the test asks for one, and installs the test's script for the fake agent. When the test ends, also on a failure, the harness removes both directories and stops any process it started.

These two parts are the command-line seam: later tickets run werk commands against such a project and read the exit code, the output, the log and the fake's launch records.

## Acceptance criteria

- [ ] A test that spawns the agent by name with no explicit environment starts the fake, not a real agent.
- [ ] Inside a test, no variable that points at a real project log is set.
- [ ] A fresh project has a git repository and no map events.
- [ ] After a failing test, its project directory no longer exists.
- [ ] Two tests that write to their projects see none of each other's data, in any run order.
