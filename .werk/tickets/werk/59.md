## What to build

After a merge, a user path that must work does not work on the merged product. Make it work. Each path, word for word:

Scenario: A crashed agent marks its tab and tells the other tabs
Given a person has two conversations in tabs, "A" and "B"
And the agent in tab "A" exits with code 1 and an error message while the person looks at tab "B"
Then the "A" chip blinks red
And the pane of tab "B" shows one line that names tab "A" and its error
When the person switches to tab "A"
Then the pane of tab "A" shows the whole error
When the person sends a new message in tab "A"
Then a new agent starts for tab "A" and replies
And the "A" chip stops blinking red
And the line about tab "A" is gone from the pane of tab "B"

## Before you build (#st-heldout-unbuilt-close)

Check two facts for each path. First, the path needs a capability that the main line does not provide and that another ticket, one that is not merged yet, builds. A capability is an operation of the command line, a screen or route, a field or kind of event in the log, or a behaviour of an agent. Second, the seam behind the path has unit tests that state its outcome, and they pass on the main line. When both facts hold for every path, change no code: the paths are not run until that ticket merges. When the second fact fails for a path, write the missing unit test at the seam and change nothing else for that path.

## Acceptance criteria

- [ ] A user can follow "A crashed agent marks its tab and tells the other tabs" from start to end, or both facts above hold for it and a passing unit test at its seam states its outcome
