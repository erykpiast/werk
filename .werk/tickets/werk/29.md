## What to build

Each project has a board log beside the decision log, one event per line. It holds ticket events (planned, moved, reordered, archived, restored, build started, pass, build ended, merge, steps, held-out result, follow-up) and run events (tier, gate waiting, gate passed, run started, run ended, plan started, plan step, plan ended). A ticket id is the plan's subtree id, a slash, and a two-digit number; its text stays in werk's store for the project.

One pure fold turns the log into the board: five columns (blocked, ready, building, merging, done), the order inside ready, each ticket's retry count, blocking reasons, branch, builds and held-out results, and the plans. A person's moves are rules in code: ready to building only with no open blocker, building to ready, and archive only from ready, blocked or building. A build session counts as running only while the log has its start and no end and its process is alive.

The ticket verb's restore subverb appends one restore event; the fold ends the archive and keeps every other field. A ticket that is not archived, or a number not on the board, is refused and nothing is appended.

## Acceptance criteria

- [ ] A hand-written board log folds into the right columns and order.
- [ ] An archived blocked ticket comes back to blocked with its old reason after restore.
- [ ] Restoring a ticket that is not archived exits 1 and appends nothing.
- [ ] A build start whose process is dead does not count as running.
- [ ] The board fold passes the coverage gate.
