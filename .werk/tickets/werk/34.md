## What to build

The build verb runs the builder loop on one ticket in a worktree of the target repository, branched off the main line's tip, with a retry cap of 5 by default and every time limit a parameter. Each pass starts a fresh builder agent through the agent runner. Its prompt starts with the implement skill, then the ticket, the spec lines of its stories, its cited cards with their rejected options, its checks, the index of decided cards from the search operation, the instruction to search the map before deciding, and the last failure cut to about 4000 characters. The first pass is told nothing is done yet; later passes read git history only.

After the agent exits, the loop commits what it left and runs the ticket's checks in order, stopping at the first red one. A red check runs once more on the same commit: green makes the cause flaky and the pass goes on; a crash, timeout or missing tool is check infrastructure. Each step is written to the pipeline log and each session's start and end to the board log.

A green build moves the ticket to merging with its branch. A build red at the cap moves it back to ready with the reason. About once a second the loop reads the board; an archive of its ticket stops the agent, commits nothing of that pass, merges nothing, removes the worktree and keeps the branch.

## Acceptance criteria

- [ ] A scripted builder that makes the checks pass on pass 2 moves the ticket to merging after two passes.
- [ ] A builder that never passes stops at the cap and moves the ticket to ready with the reason.
- [ ] A red check that passes on its rerun records flaky and does not fail the pass.
- [ ] The launch record of pass 2 holds the last failure and the decided-card index.
- [ ] Archiving the ticket during a pass stops the fake within about a second, and the branch remains.
