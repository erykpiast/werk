## What to build

The serve verb starts the server under Bun's hot reload. It takes a lock in the log's directory in one create step that fails when the lock exists. The loser reads the lock: a dead pid is stale and is taken over; a live pid is waited on, then refused with the holder's pid and port; a lock that does not parse counts as held during the wait and as stale at its end.

A guard on the global object keeps the listening server, its live connections and its long-lived children. A hot reload evaluates the start-up again, swaps in the new request handler and logs that it reuses the live server; it never listens twice or starts a second child.

Every request that changes state or starts an agent needs the token the server makes at each start and puts in the page it serves, and a loopback Host. A read-only request needs no token. The token never goes into a log, a transcript or an agent's environment. A request that throws answers 500 and the process stays up.

The read API is card-scoped: one card with its neighbours' ids and titles, and a shape query with ids, kinds, statuses, edges, rollups and marks but no bodies.

## Acceptance criteria

- [ ] A second serve on the same project waits, then refuses with the first server's pid and port.
- [ ] A stale lock from a killed server is taken over.
- [ ] A test that edits a route handler in a copy of the app sees the edit live with no restart, and the server pid stays the same.
- [ ] A changing request without the token, or with a non-loopback Host, is refused.
- [ ] A request that makes a handler throw answers 500, and the next request succeeds.
- [ ] The shape query holds no card body.
