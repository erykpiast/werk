## What to build

After a merge, a user path that must work does not work on the merged product. Make it work. Each path, word for word:

Scenario: The executable serves the client from an empty folder
Given the release build has made the executable for the build machine
And the person copies only that executable into a new empty folder
And the machine has no source folder of werk and no separate Bun install on the path used
When the person starts the executable in that empty folder
Then werk starts and prints the address where it serves
And the person opens that address in a browser
And the werk client page loads and shows its screen with no missing file error
And no new folder of werk files appears next to the executable

## Before you build (#st-heldout-unbuilt-close)

Check two facts for each path. First, the path needs a capability that the main line does not provide and that another ticket, one that is not merged yet, builds. A capability is an operation of the command line, a screen or route, a field or kind of event in the log, or a behaviour of an agent. Second, the seam behind the path has unit tests that state its outcome, and they pass on the main line. When both facts hold for every path, change no code: the paths are not run until that ticket merges. When the second fact fails for a path, write the missing unit test at the seam and change nothing else for that path.

## Acceptance criteria

- [ ] A user can follow "The executable serves the client from an empty folder" from start to end, or both facts above hold for it and a passing unit test at its seam states its outcome
