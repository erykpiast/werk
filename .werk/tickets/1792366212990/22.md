## What to build

The builder loop is complete: implement, check, grade, review. After the grader passes, five reviewer agents run at the same time, one per area: design, maintainability, tests, security and dependencies, performance. Each reads only the diff and returns findings with a severity, a file and a line, an impact and a fix. A CRITICAL or HIGH finding fails the pass and goes into the next pass with the brief. MEDIUM and LOW findings do not block and are recorded per ticket, so a later trend report has its input; no trend report is built. A fail at any step starts a fresh pass in the same worktree. A retry cap, default 5, stops a loop that does not converge and keeps the branch.

## Acceptance criteria

- [ ] Five fake reviewers start for a pass after the grader passes, one per area.
- [ ] A HIGH finding fails the pass, and the next pass's prompt holds it.
- [ ] A pass with only MEDIUM and LOW findings passes, and the findings are in the ticket's record.
- [ ] A ticket that stays red stops after 5 passes with its branch kept, and the cap is a parameter.
- [ ] No trend report is produced.
