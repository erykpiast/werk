## What to build

For each shell call in flight, the overseer reads the process tree: the CPU time, the output written, and the open network connections. It applies #lp-overseer-inflight's table. CPU time or output that grows means working. Both flat for 60 seconds, with one connection to a host that does not answer or with no connection, means frozen.

A frozen call is cancelled: the overseer kills its process tree. The agent must learn why. First find out how the evidence can reach the agent with the call's result. If it cannot go in the result, put it in the agent's next input and say so in the ticket's notes.

The 60 seconds is a parameter. Each reading and each cancel goes to the event log, with the evidence.

## Acceptance criteria

- [ ] One test per row of the table: a fixture process for each row gets the right reading.
- [ ] A frozen fixture process is killed, with its children.
- [ ] The agent sees the evidence: the reading and the numbers behind it.
- [ ] A long command that keeps writing output is never cancelled.
