## What to build

A person who types `#` and an id into the header search box gets the card with that exact id first, then ids that start with the query, then ids that contain it; titles and reasons do not match a hash query. Enter opens the first row. Without the hash, ids, titles, reasons and findings all match.

Each row shows a dot, the title, and the card id in a small grey monospace label at the right edge, with no kind word. The dot is green for decided, amber for open, blue for proto, red for a stale card whatever its status, and split along a diagonal for a postponed card, the upper-left half in its status colour and the lower-right half grey. An option, a source and an excerpt get the colour of their kind: orange, purple and grey.

Close any gap the header search still has against this behaviour, and cover every case with a browser test on a fixture map that holds one card of each state and kind.

## Acceptance criteria

- [ ] `#werk-stack` lists werk-stack first, then its options, then an id that only contains the query; Enter opens werk-stack.
- [ ] `werk-stack` without the hash also lists a card whose title holds the word.
- [ ] A hash query that matches no id keeps the list closed.
- [ ] Each row shows the id label at its right edge and no kind word.
- [ ] A decided, open, proto, stale and postponed card each show their dot; an option, a source and an excerpt show their kind colour.
