## What to build

After a merge, a user path that must work does not work on the merged product. Make it work. Each path, word for word:

Scenario: Builder and reviewer roles resolve to Sonnet, and only the builder has an advisor
Given a scripted plan has produced a ticket on the board
When I start the run and the builder agent launches for the ticket
Then the launch record of the builder shows the pinned Sonnet id
And the launch record of the builder shows the pinned Opus id as advisor
When the review step launches a reviewer for the design area and one for the security area
Then the launch record of each reviewer shows the pinned Sonnet id
And neither reviewer launch shows an advisor

Scenario: A role that the table does not know is reported as an error
Given werk is running with a scripted plan
When a pipeline step tries to launch an agent with a role name that is neither in the table nor the chat role
Then the launch does not start on a default model
And I see an error that names the unknown role
And no launch record shows a model for that role

Scenario: No launch uses a model alias
Given a scripted plan, a builder pass and a review have all run
When I read the launch records of every pipeline agent that started
Then each record names an exact pinned model id
And no record shows a short alias for the model or for the advisor

## Acceptance criteria

- [ ] A user can follow "Builder and reviewer roles resolve to Sonnet, and only the builder has an advisor" from start to end
- [ ] A user can follow "A role that the table does not know is reported as an error" from start to end
- [ ] A user can follow "No launch uses a model alias" from start to end
