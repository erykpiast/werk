## What to build

The client lives in its own folder beside the server code: one HTML page and React roots, built from shadcn/ui components on Tailwind. In dev, the werk server runs Vite in middleware mode inside its own process, on one port; the build target writes the client into a separate output folder that the server serves outside dev. The page shows two panes: the left pane with a sticky two-row header and a body that shows one view, and the right pane reserved for the chat. Addresses are `/map/<id>` (URL-encoded, `/map` opens the root card) and `/board`; the server answers every view address with the app; an unknown or removed id shows a page that says so. A React island renders the open card's title from the card read.

The page fetches the map each time its live channel connects, and reads again on every changed signal. `make dev` runs the server under Bun hot reload: a server module edit evaluates the start-up again, the guard on the global object keeps the listening server, live channels and children, swaps in the new request handler and logs that it reuses the live server. A client change Vite cannot apply in place reloads the page; the composer draft is kept in session storage per tab.

Component tests run under `bun test` with one DOM registered per test process before any test file loads; the runtime's network, stream and timer globals are put back afterwards; each test unmounts what it rendered. The browser harness starts a real werk server per test on a copy of a fixture project and, for reload tests, on a copy of the app with its own Vite dependency cache; it refuses to start when the fake agent is not first on the search list, and writes a PNG per test as evidence. Tests pass on DOM and accessibility-tree assertions.

## Acceptance criteria

- [ ] `/map/<id>` shows that card's title; Back and Forward move between visited cards; an unknown id shows a not-found page.
- [ ] A command-line add while the page is open redraws it without a reload.
- [ ] A page whose server restarts shows a write made while it was down after it reconnects.
- [ ] In dev, editing a route handler on an app copy changes the response without a new process or a dropped live channel.
- [ ] A client edit that cannot apply in place reloads the page and keeps the composer draft.
- [ ] A server unit test and a component test in one process both pass, and the server test uses the runtime network function.
- [ ] The browser harness refuses to start when the fake agent is not first on the search list.
