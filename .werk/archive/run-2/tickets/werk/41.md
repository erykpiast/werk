## What to build

`make build` compiles the server, its packages, the Bun runtime and the Vite-built client into one executable for macOS and Linux, each on ARM and Intel. The build writes a list of werk's own files (client assets, prompts, shipped subagent definitions) and embeds them; the code reads werk's own files only through that list and never discovers them by listing a folder. The same code runs from a checkout and from the executable.

Every child process werk starts, every prompt that names werk, and every command it prints names the running executable, never a runtime and a source path; one shared helper gives that name, and the existing callers move to it. A test fails if werk's own code lists a folder of its own files. The user's own files, such as the map and the target repository, are read from disk as before. No Homebrew tap or release step is built; the executables are the files a later install channel points at. Windows is not built.

This ticket comes early on purpose, so every later ticket that starts a process or names werk uses the helper and the embedded list from its first line.

## Acceptance criteria

- [ ] The executable, copied alone into an empty folder, serves the map and the client for a fixture project.
- [ ] A prompt built inside the executable names the executable's path for werk commands.
- [ ] A test fails if code lists a folder of werk's own files.
- [ ] `make build` produces the four platform files.
- [ ] From a checkout, the same code serves the client and prompts as before.
