## What to build

The merge loop builds up to three ready tickets at the same time, each in its own worktree branched from the main line's tip when its build starts. It starts a ticket next to the running ones only when the names on its touches line share none with theirs, comparing the names trimmed and in lower case; a ticket that shares a module waits until the other has merged. Which tickets may start is a pure function of the board and the touches lines. The merge queue still takes one ticket at a time.

When git cannot merge a ticket, its next pass starts from its own branch with the main line's tip merged in; the builder gets the conflicted files and the conflict output, and names the cause conflict. That pass does not count against the retry cap. A ticket that comes back green from a conflict pass goes to the front of the merge queue. Three conflicts in a row mark it stuck, which blocks it and its dependents only.

## Acceptance criteria

- [ ] Three tickets with disjoint touches build at once; a fourth waits.
- [ ] Two tickets sharing one touches name, written in different case, never build at the same time.
- [ ] A ticket whose branch conflicts with an earlier merge gets a conflict pass from its own branch and its pass count does not rise.
- [ ] After a green conflict pass that ticket merges before any other waiting ticket.
- [ ] A third conflict in a row marks the ticket stuck.
- [ ] The scheduling function is a pure module that passes the coverage gate.
