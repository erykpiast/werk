## What to build

A build runs in its own process, apart from the server, so it can die alone: a kill, a crash, a machine sleep. The server watches for a dead build at two moments: when a build process it started exits, and when the server itself starts. A build is dead when the board log has a start for it, no end, and its named process is gone. A build whose process is alive is left alone, whichever server started it.

For each dead build the server writes its end with the reason died, then starts a fresh pass of the same ticket from the last commit on the ticket's branch, with the death as the last failure in the brief. The fresh pass counts against the ticket's retry cap, so a build that dies on every pass stops at the cap with died as the reason. Work the dead pass did not commit is lost. The death is a step end in the pipeline log too.

## Acceptance criteria

- [ ] A build process killed while the server runs gets a died end and a fresh pass starts from the branch's last commit.
- [ ] A build killed while the server is down gets its died end and fresh pass when the server starts.
- [ ] The fresh pass's prompt says the last pass died.
- [ ] A build that dies on its last allowed pass stops with died as the reason and no new pass starts.
- [ ] A live build started by an earlier server is not touched.
