## What to build

Each project has a board log beside the decision log, one event per line, and one pure fold turns it into the board: each ticket's column (blocked, ready, building, merging, done), order, blocking reason, retries, archive state, sessions and results, and the run state. Ticket events: planned, moved, reordered, archived, restored, build started, pass, build ended, merge, steps, held-out result, follow-up. Run events: tier, gate waiting, gate passed, run started, run ended, plan started, plan step, plan ended. A ticket id is `<subtree-id>/NN`, and the ticket's text stays in werk's store for the project.

Moves follow rules in code: ready to building only with no open blocker, building back to ready; only a ready, blocked or building ticket can be archived. `werk ticket list` prints the board; `werk ticket move <id> blocked|ready --reason` needs a reason; `werk ticket archive <id>` keeps the column and reason; `werk ticket restore <number> [--actor you]` appends one restore event and puts the ticket back in the column it left with its old reason. A restore of a ticket that is not archived, or a number not on the board, exits 1 and appends nothing. Every event records its actor.

## Acceptance criteria

- [ ] A sequence of planned, moved and archived events folds to the expected columns.
- [ ] A move without a reason is refused.
- [ ] Archiving a blocked ticket and restoring it puts it back in blocked with the same reason.
- [ ] Restoring a ticket that is not archived exits 1 and the board log is unchanged.
- [ ] Archiving a done ticket is refused.
- [ ] The board fold passes the coverage gate.
