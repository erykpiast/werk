## What to build

One fake stands in for every agent, so it must know which job each launch does. Every agent process that werk starts carries a role name in its environment: a short fixed word for the job. The roles are spec writer, ticket writer, builder, grader, reviewer, classifier, step author and binder, plus chat for the conversation agent. werk sets the role in production and in tests alike, and the real agent ignores it. The role names live in one module of entries, so a new kind of agent adds one entry.

A script holds replies per role. The fake reads the role of its launch and plays the reply scripted for it, not a reply picked by the prompt text or the launch order. The launch record holds the role next to the arguments.

The role also sets the fake's lifetime. In the chat role, each message on its input is one turn: the fake plays the next scripted reply and waits, and exits only when its input closes. In every other role, the fake reads the first message, plays one reply and exits with the script's code. A permission answer that arrives on the input is part of that reply, not a new turn.

## Acceptance criteria

- [ ] A script with one reply for builder and one for grader gives each launch its own reply, whatever the prompt text says.
- [ ] A build pass, its grader, its five reviewers, the loop classifier, the step author, the binder and both plan writers each show their role in the launch record.
- [ ] In the chat role, two messages give two replies, and the fake exits only after the input closes.
- [ ] In the builder role, a reply with an ask plays, the answer arrives on the input, and the fake exits with the script's code with no second turn.
