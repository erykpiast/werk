## What to build

A build verb takes one ready ticket. The worktree manager makes one worktree that branches off the tip of the main line, never a snapshot of a working tree. Each pass starts a fresh headless agent through the headless runner, with the ticket, its stories, the decided cards in its depends_on closure, and the last failure cut to about 4,000 characters. When the agent exits, the loop commits the worktree as that pass.

The check runner runs the ticket's checks, each one command and its exit code, and stops at the first red. Red saves the failure and starts a new pass. A retry cap, default 5, stops a loop that does not converge and keeps the branch.

Each pass appends one line to the run record: check results, time and cost. The board log moves the ticket to building and records its retries. Every time limit is a parameter.

## Acceptance criteria

- [ ] In a temporary repository, a fake builder that fails once then passes gives two pass commits and a green result.
- [ ] The second pass's prompt holds the first failure, cut to at most about 4,000 characters.
- [ ] The worktree's first parent is the main line's tip at the start of the build.
- [ ] A fake builder that never passes stops at 5 passes, and the branch stays.
- [ ] The run record has one line per pass with check results, time and cost.
- [ ] The board shows the ticket in building with its retry count.
