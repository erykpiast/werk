## What to build

The ticket format module reads a ticket file into its fields: five header lines (title, cites, blocked_by, stories, touches) in that order, then three sections (What to build, Acceptance criteria, Checks) in that order. Cites, blocked_by, and stories may be empty, and Checks may have no bullet, but each line and each heading must be present. Cites take ids with or without the hash sign. Blocked_by and stories take numbers separated by commas. Touches take module names as concepts.

The ticket checks run the eight checks on one ticket, read from the file alone (#st-ticket-own-checks), and the three checks on the whole set (#st-ticket-set-checks): every required card is cited, every story is delivered, and blocked_by names real tickets with no cycle. A failed set check names the tickets it blocks (#st-ticket-partial). A touches entry that looks like a file path fails. Blocked_by is read as the planner wrote it and is never derived from card links.

`werk ticket check <dir>` runs both groups and prints each failure with the ticket and the field.

## Acceptance criteria

- [ ] A ticket that lacks its touches line fails, and the message names "touches" and the ticket.
- [ ] A ticket with the sections in the wrong order fails and names the section.
- [ ] A ticket with an empty cites, blocked_by, and stories and a Checks heading with no bullet passes the shape check.
- [ ] A touches entry with a slash or a file extension fails.
- [ ] A set that leaves a required card uncited or a story undelivered fails and names the card or the story.
- [ ] A blocked_by cycle fails and names only the tickets in the cycle.
- [ ] The ticket format and the ticket checks have unit tests and are on the pure-file list of the coverage gate.
