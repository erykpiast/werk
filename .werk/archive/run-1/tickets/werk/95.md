## What to build

A test writer asks the harness for a project and gets a fresh directory with a git repository and an empty map. This works the same way for a command-line test, a server test and a browser test. When the test's scope ends, the harness removes the directory and stops any server that serves it, also when the test fails. No test reads what another test wrote.

Before the first unit test, the run removes every environment setting that points at a real project, so no test can reach the map a person works in. It puts the fake agent first in the program search list. It also makes process spawn, program lookup and the shell default to that cleaned environment. A test that starts an agent and passes no environment of its own still finds the fake. A process that a harness starts inherits the same cleaned environment.

The browser test server checks at start-up that the fake agent is first in the program search list, and refuses to start when it is not. A leak then fails at once.

Every make target runs inside v0's own repository. It installs the locked packages first when they are missing, so a fresh clone or a fresh worktree passes its checks with no manual step.

## Acceptance criteria

- [ ] Two tests that each write a card see only their own card, and both project directories are gone after the run, also when one test fails.
- [ ] A server test's server is stopped when its scope ends.
- [ ] A test that sets a project setting in the environment before the run reads no such setting inside a test.
- [ ] A test that starts the agent by name, with no environment of its own, gets the fake agent's reply.
- [ ] The browser test server, started with a search list where the fake is not first, exits non-zero with a message that names the cause.
- [ ] In a fresh clone with no installed packages, `make test` installs the locked packages and passes.
