## What to build

The map's only store is an append-only log of events in the project directory. The log module can append an event and read every event. It never rewrites or deletes one. The fold is a pure function from the event list to the map state: each node with its latest title, why, body, kind, status, and who.

`werk add` appends a proposed-card event, a separate event type from an added card. Every kind — card, option, source, excerpt — enters as a ghost under its proposed refines parent. The output says "proposed". A second add with the same id refuses. A change to the title, the why, or the body of a ghost refuses. The only correction is a discard, then a new add.

`werk accept <id>` refuses unless it carries the claim that the person asked for it. With the claim, it commits the card and every ghost refines ancestor above it, up to the first real card. `werk discard <id>` drops the ghost and every ghost descendant. Accept is one card at a time.

`werk show <id>` reads the fold and prints the card with its proposed flag, status, and parent. The command line is the agent's only write path to the map: every verb appends through the log module.

## Acceptance criteria

- [ ] Every verb in this ticket adds events to the end of the log and never changes an earlier line.
- [ ] A retitle of a real card shows only the new title in the fold, and the old title stays in the log.
- [ ] An add of each kind prints "proposed" and appears in the fold with the proposed flag under its proposed parent.
- [ ] A second add with the same id exits non-zero. An edit of the title, the why, or the body of a ghost exits non-zero.
- [ ] An accept without the person's claim exits non-zero and leaves the card a ghost.
- [ ] An accept with the claim on a ghost child under two ghost parents commits all three.
- [ ] A discard of a ghost parent also removes its ghost children from the fold.
- [ ] The fold has unit tests and is on the pure-file list of the coverage gate.
