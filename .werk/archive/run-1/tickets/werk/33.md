## What to build

A test can put one fake agent binary first on the PATH under the name of the real agent. A test gives it a script. The fake reads its arguments and its input the way the real agent does, replays the scripted stream of stream-json events on its output, edits files in its working directory as the script says, and exits with the scripted code.

The same binary plays every role: the chat agent (a long-lived child that reads stream-json turns on its input), a headless one-shot agent, the builder, the grader, the reviewers, the classifiers, the step author, the binder, and the spec and ticket writers. A script can choose its replies by role, by turn, and by pass number. A script can also ask a permission question, stay silent, repeat a tool call, or die mid-turn, so later tickets can test those cases.

The fake records each call (arguments, input, working directory) where the test can read it.

## Acceptance criteria

- [ ] A command-line test runs the fake with a script, reads the scripted events from its output, and sees the files the script edits.
- [ ] A long-lived fake reads two stream-json turns on its input and answers each one with its scripted events.
- [ ] A fake started with the resume or fork option records that option, and a fork gets a new session id.
- [ ] A script can emit a permission ask, emit nothing for a set time, repeat one tool call, and exit mid-turn with a non-zero code.
- [ ] A test reads the record of every call the fake got.
- [ ] No test in the suite starts the real agent.
