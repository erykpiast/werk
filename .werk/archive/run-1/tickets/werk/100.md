## What to build

The rules for writing cards live in one instructions text. werk adds it to the system prompt of every agent it starts that can write to the map: the chat agent first of all.

The instructions state the wording rules. A card describes its own subject, not the session that wrote it: no narration of who said what, no edit history, no note of where the text came from. A card names behaviour and concepts, never a file, a function, a class, a constant, a line number or an internal endpoint. A card does not list its child cards.

The instructions also state the read-before-write rule. Before an agent writes a card, it reads that card from the map, so a stale context in its own tab never leads to a wrong write.

## Acceptance criteria

- [ ] The fake agent's launch record for a chat conversation shows the instructions text in its system prompt.
- [ ] The instructions text holds the rule against session narration and edit history.
- [ ] The instructions text holds the rule against file, function and line names.
- [ ] The instructions text holds the rule to read a card from the map before writing it.
