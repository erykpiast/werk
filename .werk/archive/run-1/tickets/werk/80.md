## What to build

The ticket parser reads a ticket file: five header lines in order (title, cites, blocked_by, stories, touches), then three sections in order (What to build, Acceptance criteria, Checks).

The own checks run on one file alone: title, shape, size of 4000 characters or fewer, what-to-build, acceptance, no-file-paths, make-targets, and touches. A shape failure names each missing line or heading. A touches name with a slash, a backslash or a file extension fails.

The set checks run on the tickets that passed their own checks, the decided cards of a subtree read from the map, and a spec's story numbers: every decided card is cited, every story is delivered and no unknown story is listed, and every blocked_by number is in the set with no cycle. A blocked_by failure names only the tickets that must not start.

The ticket-check verb takes a folder, a subtree root and a spec, runs both groups, prints each failure with its ticket and field, and exits non-zero when any check fails. The plan calls the same checks later, and an agent that changes a ticket runs this verb again.

## Acceptance criteria

- [ ] A fixture folder of valid tickets passes with exit code zero.
- [ ] A ticket with no touches line fails shape, and the output names the ticket and the touches field.
- [ ] Each own check has one fixture that breaks only it, and the output names that check.
- [ ] A set with an uncited decided card, a missing story, an unknown blocker, and a cycle fails each set check, naming the card, the story and the tickets.
- [ ] Parser and checks are pure and on the pure-file list.
