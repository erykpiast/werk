## What to build

The builder loop is complete: implement, check, grade, review, in that order. The checks stop at the first red, the grader runs only on green checks, and the review only after the grader passes. There is no separate fix step. After the grader passes, five reviewer agents run at the same time, one per area: design, maintainability, tests, security and dependencies, performance. Each reads only the diff in a fresh context and returns findings, pointing at the diff or at code it directly affects, with a severity, a file and a line, an impact and a fix. A CRITICAL or HIGH finding fails the pass and goes into the next pass with the brief. MEDIUM and LOW findings do not block and are recorded per ticket, so a later trend report has its input; no trend report is built. A fail at any step starts a fresh pass in the same worktree. A retry cap, default 5, stops a loop that does not converge and keeps the branch.

## Acceptance criteria

- [ ] Five fake reviewers start for a pass after the grader passes, one per area.
- [ ] A HIGH finding fails the pass, and the next pass's prompt holds it.
- [ ] A pass with only MEDIUM and LOW findings passes, and the findings are in the ticket's record.
- [ ] A ticket that stays red stops after 5 passes with its branch kept, and the cap is a parameter.
- [ ] No trend report is produced.
- [ ] A pass with a red check starts neither the grader nor the reviewers, and a failed grade starts no reviewer.
- [ ] A fail at check, grade or review starts the next pass with that failure in its prompt.
- [ ] At the cap the loop exits non-zero, and a test sets the cap to 2.
