## What to build

The run verb starts the merge loop on a plan run. Nothing builds before it, and this one start triggers the whole run. The scheduler starts a ticket when every blocker is merged and no failed set check holds it. Up to 3 tickets build at the same time, each in its own worktree off the main line's tip at its start. A ticket starts next to the ones already building only when its touches names and theirs share none; the comparison is of the names alone. The merge queue still takes one ticket at a time. The cap is a parameter.

## Acceptance criteria

- [ ] Before the run verb, no ticket of a plan run builds.
- [ ] Four unblocked tickets with distinct touches start three builds, then the fourth after one merges.
- [ ] Two tickets whose touches share a module never build at the same time.
- [ ] A ticket whose blocker is not merged does not start.
