## What to build

The Markdown renderer for card text makes card references into links and boxes fenced code. In a card body, a why line, a finding line and a notes thread, a `#id` that the map knows becomes a link to that card's route. A bare id links only when it has a hyphen or a colon. A code span links only when it holds nothing but an id. Bold and italic markers inside a code span stay literal. A dead id, a bare single word, a command in a code span, a fenced block, a heading and a URL fragment stay as they are. The summary of a card in a grid tile has no links. Fenced code renders in a box, with syntax highlighting for json, js, ts and bash, and scrolls sideways. The renderer does not reformat the code.

## Acceptance criteria

- [ ] `#known-id` links and `#unknown-id` stays plain text.
- [ ] `al-diff` and `pr-iface:opt0` link bare. `align` without a # does not link.
- [ ] A code span with only an id links. A code span with a command and an id in it stays code.
- [ ] A fenced block, a `# heading` and a URL fragment are not changed by the link rule.
- [ ] A grid tile summary contains no link element.
- [ ] A long fenced line scrolls sideways inside its box, and the indentation in the source shows unchanged.
- [ ] A click on a rendered link opens the card on the map.
- [ ] The renderer is on the pure-file list of the coverage gate.
- [ ] Bold and italic markers inside a code span render literally.
- [ ] A fenced json, js, ts or bash block is highlighted.
