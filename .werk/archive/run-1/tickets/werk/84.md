## What to build

After the checks pass, a grader agent reads the diff. It scores one delivery line per acceptance criterion and one contradiction line per decided card in the ticket's depends_on closure, cited or not. Each line has a score from 1 to 5, where 3 passes, and the gap with the file, line or test that shows it. The grader's brief states that a part of a card the diff does not build yet passes its contradiction line, because another ticket builds it.

After the grader passes, five reviewer agents run at the same time, one per area: design, maintainability, tests, security and dependencies, performance. Each sees only the diff. Each finding has a severity, a file and a line, the impact and a fix.

A grader fail, or a CRITICAL or HIGH finding, fails the pass, and the gaps and findings go into the next pass's prompt. MEDIUM and LOW findings do not block; the run record keeps them per ticket, so a later trend report has its input. No trend report is built.

## Acceptance criteria

- [ ] A fake grader that scores a card 2 fails the pass, and the next prompt holds the gap.
- [ ] The grader gets one line per decided card in the closure, including a card the ticket does not cite.
- [ ] A fake grader that marks a card part as not built yet, with score 3, lets the pass go on to the review.
- [ ] The grader's brief holds the rule that an unbuilt part of a card passes its contradiction line.
- [ ] Five fake reviewers start for one pass, one per area.
- [ ] A HIGH finding fails the pass; a pass with only MEDIUM and LOW findings goes green, and the run record holds them.
