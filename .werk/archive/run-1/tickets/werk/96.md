## What to build

The command-line, server and browser tests share one fake agent. It is found first in the program search list under the real agent's name, and at launch it reads the script that the harness installed in its temporary project. With no script installed, it exits with an error and never invents an answer.

A script is an ordered list of steps plus an exit code. A step is either an event, printed as one line of the agent's output stream, or an edit, a file written at a path relative to the project. The fake plays the steps in order and then exits with the script's code. So a test can check which file was on disk when each event arrived.

An edit whose path leads outside the temporary project fails, and the fake writes nothing there.

Each launch records its arguments in the temporary project, so a test reads what werk asked the agent.

## Acceptance criteria

- [ ] A script with an event, an edit and a second event: when the second event arrives, the edited file is on disk; when the first arrives, it is not.
- [ ] The fake exits with the script's exit code after its last step.
- [ ] An edit to a path with a parent-directory step that leaves the project fails, and no file is written outside the project.
- [ ] After two launches, the launch record holds the arguments of each launch in order.
- [ ] With no script installed, the fake exits non-zero with an error that says no script is installed.
