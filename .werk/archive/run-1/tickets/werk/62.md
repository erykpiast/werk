## What to build

The decision log is an append-only file of events. It appends and reads, and never rewrites or deletes an event. Every read goes through the fold: a pure function from the event list to the map state, with the latest title, body, why, status and who of each card.

The command line is the only write path to the map. The add verb proposes a card, an option, a source or an excerpt kind as a ghost: a proposed event of its own type, not a flag on an added card. Its output says "proposed". A ghost sits in the fold with a proposed flag.

The accept verb turns one ghost into a real card. It refuses unless the call states that the person asked for it (the actor claim). The show verb prints one card with its fields and its proposed state. The edit and retitle verbs change the words of a real card by appending an event, and refuse on a ghost, because a ghost's words are frozen. A second add with the same id refuses too.

## Acceptance criteria

- [ ] Each map verb appends exactly one event to the end of the log and never changes an earlier line.
- [ ] After a retitle, the show verb prints only the new title, and the old title stays in the log.
- [ ] The add verb prints "proposed", and the show verb marks the card as a ghost.
- [ ] An edit, a retitle, or a second add on a ghost exits non-zero and appends no event.
- [ ] The accept verb exits non-zero without the actor claim, and with it the card shows as real.
- [ ] The fold has unit tests and is on the pure-file list of the coverage gate.
