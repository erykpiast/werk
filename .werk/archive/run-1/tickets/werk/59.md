## What to build

After a merge, a user path that must work does not work on the merged product. Make it work. Each path, word for word:

Scenario: A person opens the served page and sees the empty map and the composer
Given a project directory with a fixture log
When the person runs `werk serve` in that project
And the person opens the address that the server prints in a browser
Then the browser shows a page that React renders
And the page shows an empty map shell
And the page shows a composer box that accepts typed text

Scenario: A second server on the same project waits for the lock, then refuses
Given a person runs `werk serve` in a project, and the server is live
And the lock wait for a new server is set to a few milliseconds
When the person runs `werk serve` a second time in the same project
Then the second server prints that it waits for the process id of the live server
And after the wait, the second server exits with a non-zero status
And its message names the port and the process id of the live server
And the first server still serves the page

Scenario: An edit to a server module reloads it in the same process, and a live child survives
Given a person runs `npm run dev` in a project
And the server has started a long-lived child before any edit
And the person notes the process id of the server
When the person edits a server module and saves it
Then the server output shows that it reuses the live server and does not listen a second time
And the server process id is the same as before the edit
And the child that started before the edit is still alive
And a new browser connection to the live channel sees the same server state as before the edit

Scenario: A change to the project's log reaches an open page without a manual refresh
Given a person runs `werk serve` in a project
And the person has the page open in a browser
When an event is appended to the project's log file
Then the live channel sends "changed" to the open page
And the page fetches the map again without a manual reload

Scenario: A client change that cannot apply in place reloads the page and keeps the composer draft
Given a person runs `npm run dev` in a project
And the person has the page open and types a draft into the composer
When the client code changes in a way that cannot apply in place
Then the live channel sends "reload" to the open page
And the page reloads itself
And after the reload, the composer holds the same draft that the person typed before

Scenario: One script picks replies by role and by pass number in a build
Given a temporary project with a git repository and a ticket ready to build
And a fake agent is first on the PATH under the name of the real agent
And a script gives the builder a file edit, the grader a fail verdict on pass 1, and the grader a pass verdict on pass 2
When the user runs the build command for the ticket
Then the builder edits appear as commits on the ticket branch
And the event log shows a failed grade followed by a passed grade
And the call record shows calls in the builder role and two calls in the grader role
And no call in the record reached the real agent

Scenario: Every kind an agent adds enters as a frozen ghost under its proposed parent
Given a map with one real card "Root"
When the agent adds a card "Plan" that refines "Root"
And the agent adds an option, a source, and an excerpt that each refine "Plan"
Then each add prints "proposed"
And showing each new id prints it as proposed, under its proposed parent
And showing "Root" prints it as a real card, not proposed
When the agent adds a card again with the id of "Plan"
Then the add fails with a non-zero exit
And showing "Plan" still prints its first title, why, and body

Scenario: A ghost's words are frozen, and the only correction is a discard and a new add
Given the agent has proposed a card "Draft" under a real card
When the agent tries to change the title of "Draft"
Then the command fails with a non-zero exit
When the agent tries to change the why of "Draft"
Then the command fails with a non-zero exit
When the agent tries to change the body of "Draft"
Then the command fails with a non-zero exit
And showing "Draft" prints the words it had when it was proposed
When the agent discards "Draft"
And the agent adds "Draft" again with a new title
Then the add prints "proposed"
And showing "Draft" prints the new title as proposed

Scenario: An accept commits only when it claims the person asked, and it brings the ghost ancestors with it
Given a real card "Root"
And the agent has proposed "Parent" under "Root", "Middle" under "Parent", and "Leaf" under "Middle"
When the agent accepts "Leaf" without stating that the person asked for it
Then the accept fails with a non-zero exit
And showing "Leaf" still prints it as proposed
When the agent accepts "Leaf" and states that the person asked for it
Then showing "Leaf", "Middle", and "Parent" prints each one as a real card, not proposed
And showing "Middle" prints "Parent" as its parent
And showing "Root" prints it unchanged

Scenario: A discard of a ghost parent removes its ghost children
Given a real card "Root"
And the agent has proposed "Parent" under "Root" and "Child" under "Parent"
And a real card "Sibling" sits under "Root"
When the agent discards "Parent"
Then showing "Parent" reports that the map has no such card
And showing "Child" reports that the map has no such card
And showing "Sibling" still prints it as a real card under "Root"

Scenario: The log only grows, and the map shows only the latest title
Given a real card "Use a log"
And the person saves a copy of the log file
When the agent changes the title of that card to "Use an append-only log"
And the agent proposes a new card, then discards it
And the agent proposes another card and accepts it with the claim that the person asked
Then showing the first card prints only the title "Use an append-only log"
And the log file still contains the title "Use a log"
And the saved copy of the log is an exact start of the current log file, with each new event as a new line after it
