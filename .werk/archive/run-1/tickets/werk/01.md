## What to build

A new, empty repository holds werk v0. Nothing is copied from the prototype. `werk serve` starts one Bun server that serves a React page transformed by Vite. The page shows an empty map shell. In dev, the server runs under `bun --hot`. A guard on the global object stops a hot reload from starting a second server or a second set of long-lived children, so an edit to a server module reloads that module in the same process.

The agent that builds werk can see what it builds. Three commands work from the first commit: the unit tests, the coverage run with a 90% gate over an explicit list of pure files, and the browser tests that boot the real server on a copy of a fixture project. One scripted fake agent binary exists and goes first on the PATH in every test, so no test reaches a real agent. A harness makes a temporary project directory and a temporary git repository for command-line tests.

## Acceptance criteria

- [ ] The repository contains no code copied from the prototype.
- [ ] `werk serve` in a project directory serves a page that React renders, and the browser test suite opens it.
- [ ] Under the dev command, an edit to a server module reloads it, the process id stays the same, and a long-lived child started before the edit is still alive after it.
- [ ] A second hot evaluation of the start-up code logs that it reuses the live server and does not listen a second time.
- [ ] The unit test command runs server tests and React component tests.
- [ ] The coverage command fails when a file on the pure-file list is under 90%, and passes when every listed file is at or over 90%. Plain unit tests do not check coverage.
- [ ] The browser test command boots a real server on a copy of a fixture project, with the fake agent first on the PATH, and saves one screenshot per test as evidence.
- [ ] A command-line test can make a temporary project and git repository, run a werk command against it, and read its exit code and output.
- [ ] A new connection to the live channel after a hot reload sees the same server state as before the edit.
- [ ] No test reaches a real agent.

## Checks

- `make test-coverage`
