## What to build

`werk serve` starts one Bun server for a project directory. It serves a React page that Vite transforms inside the server process, a read API, and one live event channel (SSE). The page shows an empty map shell and a composer box.

Under the dev command the server runs under `bun --hot`. A guard on the global object stops a hot reload from starting a second server or a second set of long-lived children, so an edit to a server module reloads that module in the same process and a live child survives it.

A second server start on the same project waits up to 5 seconds for the lock, then refuses with a message that names the live holder. A listen that hits an address in use retries every 250 ms, up to 20 times. Every limit is a parameter.

The live channel pushes "changed" when the project's log file changes and "reload" when client code changes in a way Vite cannot apply in place. Before a reload, the page keeps the composer draft in session storage and puts it back after the reload.

The browser test harness boots a real server on a copy of a fixture project, with the fake agent path first on the PATH, blocks outside script hosts, clears local storage, and saves one screenshot per test as evidence.

## Acceptance criteria

- [ ] `werk serve` serves a page that React renders, and a browser test opens it.
- [ ] Under the dev command, an edit to a server module reloads it. The process id stays the same, and a child started before the edit is still alive after it.
- [ ] A second hot evaluation of the start-up code logs that it reuses the live server and does not listen a second time.
- [ ] A new connection to the live channel after a hot reload sees the same server state as before the edit.
- [ ] A second `werk serve` on the same project waits for the lock, then exits non-zero with a message that names the holder. With the wait set to milliseconds, the test runs fast.
- [ ] A change to the log file pushes "changed" on the live channel.
- [ ] A client change that cannot apply in place pushes "reload". After the reload, the composer still holds the text typed before it.
- [ ] Each browser test saves a screenshot, and asserts on page structure, not on the image.
