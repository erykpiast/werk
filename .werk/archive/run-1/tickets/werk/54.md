## What to build

When a builder loop starts, a step author agent starts too. It writes the ticket's held-out steps from the brief as Given/When/Then lines, each one a whole user path. A binder agent turns the steps into tests and never makes a test pass. The steps and the bound tests are stored outside every worktree and every prompt that a builder gets, so the builder never sees them.

`werk heldout` runs the held-out set on the tree of the main line and prints each step green or red. A step the binder could not run is reported as not run, not red. On a red step while the builder loop still runs, the builder's next pass gets the text of the failed step, not the test.

`werk gate g2 <root>` refuses while any held-out step is red on the main line, and names the red steps.

## Acceptance criteria

- [ ] A build start also starts the fake step author, and the steps it writes are stored outside the worktree.
- [ ] No builder prompt and no builder worktree holds a held-out step or a bound test.
- [ ] `werk heldout` reports each step green, red, or not run, on the main line's tree.
- [ ] A red step during a build puts the step text in the next builder prompt.
- [ ] G2 refuses while one step is red, and names it.
