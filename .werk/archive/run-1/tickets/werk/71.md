## What to build

The Markdown renderer adds card links by one rule, in its own pure module. A `#card-id` links when the map knows the id. A bare id links only when it holds a hyphen or a colon, and a bare single word stays text. A code span links only when it holds nothing but an id, with or without the hash; a command in a code span stays code. Fenced blocks, headings and URL fragments stay as they are: the character before the hash must not be a word character or a slash. A dead reference stays plain text. The link is the route the map already uses for a card.

The rule applies to the card body, the why line and the notes thread. The card summary in a grid tile has no links, because the tile is a button.

Fenced code renders in a box, with highlighting for json, js, ts and bash, and scrolls sideways. The renderer never reformats the code.

## Acceptance criteria

- [ ] A body with `#known-id`, `#unknown-id`, `al-diff`, `align` and a code span with a command renders exactly one link per known id, and none for the others.
- [ ] A heading, a URL with a fragment and a fenced block that hold an id render with no link.
- [ ] A click on a link opens that card in the map.
- [ ] A grid tile summary with a card id holds no link element.
- [ ] A long fenced line scrolls sideways and keeps its indentation.
- [ ] The link rule and the renderer are on the pure-file list.
