## What to build

`werk status <id> decided` runs a program check before it appends the decided event. The check reads the four facts that #werk-contract-facts names from the fold: the who, the depends_on basis, the recorded options or the unchallenged fact, and the kill criterion. If a fact is missing, the verb exits non-zero, appends nothing, and prints the exact next command that adds the missing fact.

On a ghost, the check reads its held edges, so a ghost proposed as decided obeys the same rule. An amend of a decided card (a reopen and a decide in one step) runs the same facts again. The text of a card is not checked.

## Acceptance criteria

- [ ] A card that lacks one fact stays open, the log gains no event, and the output prints a runnable command that adds that fact.
- [ ] After the printed command runs, the same `status decided` succeeds.
- [ ] A ghost with all facts on held edges moves to decided. A ghost that lacks one fails the same way as a real card.
- [ ] An amend of a decided card that removes a required fact fails and leaves the card decided as it was.
- [ ] The check logic has unit tests and is on the pure-file list of the coverage gate.
