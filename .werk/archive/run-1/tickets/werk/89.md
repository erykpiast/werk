## What to build

The board has a control to start the merge loop on a plan run; it starts the whole run. A person reorders tickets within ready by drag. A ready or blocked ticket has an archive action that asks for confirmation; the confirmation says the ticket can be restored. A restore verb puts an archived ticket back. Inside an active run, the trigger icon or a drag into building starts one ready ticket early, and it then goes through the same merge queue. A drag of a building ticket back into ready stops its build.

These are the only manual moves. Every other column move comes from an agent or from the merge loop. The board has no control to edit a ticket's text; a person asks an agent, which runs the ticket-check verb again. Each action appends an event to the board log through the server.

## Acceptance criteria

- [ ] The start control starts the run, and tickets begin to build.
- [ ] A drag within ready changes the order the scheduler uses.
- [ ] Archive shows only on ready and blocked tickets, asks for confirmation, and the restore verb brings the ticket back.
- [ ] The trigger icon on a ready ticket moves it to building; a drag from building to ready stops the fake builder.
- [ ] A drag into merging or done is refused, and no edit control exists on a ticket.
