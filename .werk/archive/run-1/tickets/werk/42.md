## What to build

One Markdown renderer draws every card body, why line, finding line, and note. It turns a card reference into a link to that card's route in the map. Only an id the map knows links. With the hash sign, any known id links. Without it, an id links only if it has a hyphen or a colon. A code span links only when it holds nothing but an id, with or without the hash sign. A fenced block, a heading, and a URL fragment stay as they are. Bold and italic markers inside a code span stay literal.

The card summary in a grid tile gets no links, because the tile is a button.

Fenced code renders in a box with highlighting for json, js, ts, and bash, and scrolls sideways. The renderer keeps the code as the writer indented it.

## Acceptance criteria

- [ ] `#known-id`, `known-id`, and a code span with only `known-id` each render as a link to that card. A click opens the card on the map.
- [ ] `#unknown-id`, a bare single word that is an id, and a code span with a command that contains an id stay plain text or code.
- [ ] A fenced block, a heading line, and a URL with a fragment render with no link in them.
- [ ] A grid tile summary holds no link element.
- [ ] Fenced ts code renders in a box with highlight spans, keeps its indentation, and scrolls sideways when it is wider than the box.
- [ ] The renderer has unit tests and is on the pure-file list of the coverage gate.
