## What to build

`werk build <ticket>` builds one ticket. The worktree manager makes one worktree that starts from the tip of the main line, never from a snapshot of a working tree. The board moves the ticket to building.

Each pass starts a fresh headless agent through the agent runner. The prompt holds the ticket, its listed spec stories as the definition of done, the decided cards in its depends_on closure, and the last failure: the failed command and the end of its output, cut to about 4,000 characters. When the agent exits, the loop commits the worktree as "pass n". The check runner then runs each check of the ticket, one make target each, and stops at the first red. The exit code is the verdict, whatever the agent ran itself.

All green: the loop stops. Red: the next pass starts with the failure. After the retry cap (default 5, a parameter) the loop stops and keeps the branch. Each pass appends one line to the run record: check results, time, and cost. The board shows the retry count.

## Acceptance criteria

- [ ] The worktree's first commit is the main line's tip at the start of the build.
- [ ] A fake builder that edits files makes a commit named "pass 1" on the ticket branch.
- [ ] A red check in pass 1 puts the failed command and the end of its output, at most about 4,000 characters, in the prompt of pass 2.
- [ ] With two checks and the first red, the second check does not run.
- [ ] Each pass adds one run record line with the check results, the time, and the cost.
- [ ] A fake builder that never makes the checks pass stops after the cap, the branch stays, and the board shows the retry count.
- [ ] A prompt contains the ticket's listed stories and the decided cards of its depends_on closure.
