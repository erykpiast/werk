## What to build

The merge loop takes finished tickets one at a time. It makes a temporary tree of the main line's tip plus the ticket and runs the checks there. Red: nothing merges, and the ticket goes back to the builder loop with the failure. Green: the ticket merges straight onto the main line, with no integration branch.

When the main line is checked out somewhere, the merge moves that checkout by fast-forward. Local changes that block the fast-forward stop the merge, and nothing moves.

After each merge, the held-out set runs on the main line. A red step files a follow-up ticket in ready and the merge stands. The board shows a badge on the done ticket whose merge it followed, in the card and in the drawer, linked to the follow-up ticket.

G2 opens for the main line's tip when every ticket of the subtree is merged and every held-out step is green. A later merge opens it again.

## Acceptance criteria

- [ ] Two green tickets merge onto a temporary main line in order, with no other branch made.
- [ ] A ticket red on the merged tree goes back to building with the failure, and the main line does not move.
- [ ] A clean checkout moves by fast-forward; a checkout with a blocking local change stops the merge, and nothing moves.
- [ ] A red held-out step after a merge files a follow-up ticket, and the done ticket shows a badge linked to it.
- [ ] G2 opens after the last merge with all steps green, and opens again after a later merge.
