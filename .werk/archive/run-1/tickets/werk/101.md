## What to build

The dev target runs the serve verb under Bun's hot reload. A change to a server module reloads it in the same process. A guard on the global object keeps a reload from starting a second server, a second conversation manager or a second lock, so a live Claude Code child and its turn survive the edit. A new live channel connection opened after the edit still sees the running turn.

In dev, the server runs Vite inside its own process to transform the client. A client change that Vite applies in place reaches the page with no reload. A change it cannot apply in place sends a "reload" event on the live channel, and the page reloads itself. The composer draft is kept in session storage before that reload and restored after it.

A test that must edit werk's own code edits a copy of the app that the harness makes, and runs the app from that copy. The checkout stays clean, also when the test fails.

## Acceptance criteria

- [ ] An edit to a server module in the app copy during a running fake-agent turn keeps the same child pid, and the turn completes.
- [ ] After the edit, a new live channel connection sees the running turn.
- [ ] The reload logs that it reuses the live server, and the lock is not taken again.
- [ ] A client change that cannot apply in place reloads the page, and the composer draft is still there.
- [ ] After a failed hot-reload test, the checkout has no changed file.
