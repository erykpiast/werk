## What to build

After the checks pass in a pass, the grader runs as a headless agent. It reads the diff against each decided card in the ticket's depends_on closure, and returns for each card a score from 1 to 5 (3 passes) and the gap, with the file, line, or test that shows it. A score under 3 fails the pass, and the gaps go into the next pass's prompt.

After the grader passes, five reviewers run at the same time, one per quality area: design, maintainability, tests, security and dependencies, and performance. Each gets a fresh context, its area, and the diff only. Each finding has a severity, a file and a line, an impact, and a fix. A CRITICAL or HIGH finding fails the pass, and the findings go into the next prompt. MEDIUM and LOW findings do not block. The run record keeps them per ticket, so a later trend report has its input. No trend report is built.

## Acceptance criteria

- [ ] A fake grader that scores one card 2 fails the pass, and the next prompt holds that card's gap.
- [ ] The grader gets one line per decided card in the depends_on closure, not only the cited cards.
- [ ] Five fake reviewers run, one per area, and each gets only its area and the diff.
- [ ] A HIGH finding fails the pass and its fix is in the next prompt. A pass with only MEDIUM and LOW findings ends green.
- [ ] The run record holds the count of MEDIUM and LOW findings per ticket.
- [ ] A failed check in a pass starts no grader and no reviewer.
