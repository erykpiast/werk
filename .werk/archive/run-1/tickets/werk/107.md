## What to build

A person or an agent runs the ticket-check verb and reads one verdict from its exit code. A pass exits 0. A failed check exits 1. A call that could not run the checks, such as a missing folder, a missing spec or an unknown subtree root, exits 2 with a message that names what is missing. So a malformed call never reads as a pass or as an ordinary failure.

A set failure that no ticket owns, such as an uncited card or an undelivered story, names the ticket set as its place, so the reader finds where to fix without reading the rest of the output. A failure that a ticket owns still names that ticket, the check and the field.

## Acceptance criteria

- [ ] A valid fixture set exits 0.
- [ ] A set with a ticket that fails shape exits 1.
- [ ] A call with a missing spec exits 2, and the output names the spec.
- [ ] An uncited card and an undelivered story each print one line that names the ticket set, the check and the card or story.
