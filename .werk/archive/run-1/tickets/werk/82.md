## What to build

The plan verb runs over one decided subtree. It writes a feature tier event first; v0 has no way to say a tier and no way to raise it, so every gate waits for the person. Then a headless spec writer writes one spec, and a headless ticket writer splits it into ticket files. Both are the fake agent in tests.

Each writer returns a list of answer records next to its output: a slug, a title, a why, and a body. The answer proposer proposes each one as a ghost that refines the subtree root, with the agent as the one who decides. The id is the root id, a hyphen and the slug. A record the plan cannot propose, such as an id already in the map, is reported, and the plan exits with an error.

The plan runs the own checks and the set checks from the ticket-check verb's modules. The set checks read only the tickets that passed their own checks, so a ticket that is not on the board never counts as coverage for a card or a story. Tickets that pass go onto the board log as ready or blocked. A failed blocked_by check blocks only the ticket that names a blocker not in the set and the tickets on a cycle; their correct blockers still go to ready. An open ticket that the current spec no longer needs is archived with that reason.

## Acceptance criteria

- [ ] The first event of a plan run is a feature tier event.
- [ ] Fake writers' answer records appear as ghosts under the subtree root, with ids formed from the root id and the slug.
- [ ] A record whose id is already in the map makes the plan exit non-zero and name the record.
- [ ] A ticket with a missing header line is not on the board, and the output names the field.
- [ ] A card cited only by a ticket that fails its own checks is reported as uncited.
- [ ] A ticket that names a failed ticket as its blocker goes to blocked, and that ticket's other, correct blockers go to ready.
- [ ] An open ticket the new spec drops is archived with the reason on the board log.
- [ ] No plan option sets a tier other than feature.
