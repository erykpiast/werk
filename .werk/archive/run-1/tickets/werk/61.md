## What to build

v0 starts in a new git repository whose first commit holds no files. This ticket sets up the project from that empty tree: the package files for Bun, React and Vite, the folder layout, and the five make targets that every later ticket uses as its checks (test, test-coverage, typecheck, lint, e2e).

The command line has an entry point and a verb registry. Each verb lives in its own module and registers itself. The entry point finds the verbs by registration and has no central list. A help verb prints the list of registered verbs, built from the registry.

The command-line test harness makes a temporary project directory and a temporary git repository, and puts one scripted fake agent binary first on the PATH. The fake agent replays a scripted stream of events and can edit files, so no test reaches a real agent.

The coverage target runs the unit tests with coverage, then a gate that reads an explicit list of pure files and fails below 90%. Plain unit tests do not check coverage. The e2e target runs the browser test runner and passes while no browser spec exists.

Nothing is copied from the prototype. A builder may read it as a reference.

## Acceptance criteria

- [ ] The first commit of the repository holds no files, and every later commit builds on it.
- [ ] `make test`, `make test-coverage`, `make typecheck`, `make lint` and `make e2e` all exist and pass on the new project.
- [ ] The help verb prints the name of every registered verb.
- [ ] A test adds a verb module to a temporary copy of the command line and shows that the help output names it, with no edit to any other module.
- [ ] A test runs the fake agent through the harness and reads its scripted events and its file edit in the temporary project.
- [ ] The coverage gate fails when a file on the pure-file list is below 90%, and passes when it is at 90% or above.

## Checks

- `make test`
- `make test-coverage`
- `make typecheck`
- `make lint`
