## What to build

The dev target runs the serve verb under `bun --hot`. A guard on the global object keeps a hot reload from starting a second server or a second conversation manager, so a live Claude Code child and its turn survive an edit to any server module.

In dev, the server runs Vite inside its own process to transform the client. A client change that Vite cannot apply in place sends a "reload" event on the live channel, and the page reloads itself. The composer draft is kept in session storage before the reload and restored after it.

## Acceptance criteria

- [ ] An edit to a server module during a running fake-agent turn keeps the same child pid, and the turn completes.
- [ ] After the edit, a new live channel connection sees the running turn.
- [ ] A client change that cannot apply in place reloads the page, and the composer draft is still there.
- [ ] A hot reload logs that it reuses the live server and does not take the lock again.
