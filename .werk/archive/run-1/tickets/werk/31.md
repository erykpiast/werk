## What to build

werk v0 lives in a new git repository. Its first commit holds no files. No file, history, or map state of the prototype is in it. The builder may read the prototype as a reference, but copies nothing.

The first commits set up the project from the empty tree: the package files, the folder layout, and the make targets `test`, `test-coverage`, `typecheck`, `lint`, and `e2e`. The `werk` command line starts and prints its list of verbs. Each verb lives in its own module and registers itself, so a later ticket that adds a verb does not edit a shared list.

A command-line test harness makes a temporary project directory and a temporary git repository, runs a werk command against it, and reads the exit code and the output. The coverage target runs the unit tests with coverage and then fails if any file on an explicit list of pure files is under 90%. Plain unit tests do not check coverage.

## Acceptance criteria

- [ ] The repository's first commit holds no files, and its history holds no commit of the prototype.
- [ ] The repository holds no code copied from the prototype.
- [ ] `make test`, `make test-coverage`, `make typecheck`, `make lint`, and `make e2e` each exist and exit 0 on the new tree.
- [ ] `werk` with no verb prints the registered verbs and exits 0. An unknown verb exits non-zero and names the verb.
- [ ] A verb added in its own module shows in the verb list with no edit to any other module.
- [ ] A command-line test makes a temporary project and git repository, runs a werk verb in it, and asserts on the exit code and the output.
- [ ] The coverage target fails when a listed pure file is under 90%, and passes when every listed file is at or over 90%.

## Checks

- `make test`
- `make test-coverage`
- `make typecheck`
- `make lint`
