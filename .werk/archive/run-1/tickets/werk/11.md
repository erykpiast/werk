## What to build

The chat pane holds several conversations, each in a tab, and a turn in one tab does not wait for a turn in another. A new conversation forks the parent session with the fork-session option, so it shares the parent's cached prefix and history. A second, explicit control starts an empty conversation. Each conversation stores its session id and its home card: the card that was open when it started. The home card names the tab and seeds the first turn, but does not fence the conversation.

The tab strip is the last row of the pane, below the composer. Chips are real tabs, flush to the pane edges with no horizontal padding, the active chip joined to the area above it, each showing the home card id and a state dot. Cmd+1 to Cmd+5 select a tab by position, and Cmd+[ and Cmd+] step between tabs.

## Acceptance criteria

- [ ] Two conversations run fake-agent turns at the same time, and both replies stream into their own tabs.
- [ ] A fork starts its child with the parent's session and the fork-session option, and records a new session id.
- [ ] The empty-conversation control starts a child with no parent session.
- [ ] A new tab's chip shows its home card id, and its first turn starts with that card.
- [ ] A turn in a tab can name and write any card, not only cards under its home card.
- [ ] The strip is the last row of the pane, and the first chip starts at the pane's left edge.
- [ ] Cmd+2 focuses the second tab, and Cmd+] focuses the next one.
- [ ] The parent session file gains no turn from a fork.
