## What to build

Nothing builds before the person starts the run. Inside an active run, the person has four actions, and each one writes to the ticket state log through the server. They reorder tickets within ready. They archive a ready or blocked ticket after a confirmation that says it can be restored. They trigger one ready ticket early, by the trigger icon or by a drag into building; it then goes through the same merge queue. They stop a building ticket by a drag back into ready. No other column move is the person's, and a ticket is not edited on the board: the person asks an agent, and the agent runs the ticket-set checks again.

## Acceptance criteria

- [ ] After a plan and before the run starts, no ticket builds.
- [ ] A drag within ready changes the order, and the run builds in the new order.
- [ ] Archive shows only on ready and blocked tickets, its confirmation says the ticket can be restored, and an archived ticket can be restored.
- [ ] The trigger icon and a drag into building both start one ready ticket in an active run, and it reaches done through merging.
- [ ] A drag of a building ticket into ready stops its session and the pulse.
- [ ] A drag into merging or done is refused, and the board has no control that edits ticket text.
