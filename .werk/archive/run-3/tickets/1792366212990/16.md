## What to build

The plan stage runs over one decided subtree and the cards it links. A headless agent writes one spec: problem, solution, numbered user stories, implementation and testing decisions, and out of scope. A second headless agent splits the spec into tickets. Each ticket has a title, what to build, acceptance criteria, the stories it delivers, the cards it cites, blocked_by and checks, and names no file paths. blocked_by comes from the depends_on edges between the cited cards. No person answers the writers' questions; each writer returns every answer that no card gives as data, and the program proposes each one as a ghost card under the subtree.

The program then runs the ticket checks, each one command and its exit code: the checks on one ticket and the checks on the whole set (every card cited, every story delivered, blocked_by consistent). A failed set check blocks only the tickets it names. The tickets go into the ticket state log as ready or blocked.

## Acceptance criteria

- [ ] With the fake agent, a plan over a subtree writes one spec with numbered stories and at least one ticket file of the fixed shape.
- [ ] Each decision the fake writers return appears as a ghost card under the subtree.
- [ ] A ticket set that leaves one required card uncited, or one story undelivered, fails the set check, and only the named tickets are blocked.
- [ ] A ticket that names a file path, or whose blocked_by is not derived from depends_on, fails its own check.
- [ ] A ticket that delivers no story has an empty stories line and passes.
- [ ] The ticket state log holds each ticket as ready or blocked after the plan.
