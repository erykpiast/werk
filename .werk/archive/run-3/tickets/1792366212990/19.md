## What to build

A person starts a run on a plan. The first event of the run is a tier event, and the tier is always feature: every gate waits for the person. There is no spoken tier and no tier escalation. The run builds a ready ticket in its own worktree. Each pass is a fresh headless agent that gets the brief, the decided cards in the ticket's depends_on closure, and the last failure cut to about 4,000 characters. When the agent exits, the loop commits the worktree as that pass, then runs the ticket's checks itself; each check is one command and its exit code. A red check starts a new pass. Each pass writes one line to the run's record: check results, time and cost. Every time limit is a parameter.

On the board, a building ticket with a live session pulses and stops the moment the session ends. Its drawer shows a live preview of the session log, which goes away when the ticket leaves building. All of it is tested at the command line against a temporary git repository with the fake agent.

## Acceptance criteria

- [ ] Starting a run writes a tier event with the feature tier before any other run event.
- [ ] No input, word or flag changes the tier, and no gate passes without the person.
- [ ] A scripted ticket whose first pass leaves a check red and whose second pass fixes it ends green after two commits, one per pass.
- [ ] The second pass's prompt holds the failed command and the end of its output, at most about 4,000 characters.
- [ ] The run's record has one line per pass with check results, time and cost.
- [ ] The loop's own check run decides the result, even when the fake agent reports green.
- [ ] A building ticket pulses while its fake session runs and stops when the session exits, and its drawer shows a live log that is gone after the ticket leaves building.
