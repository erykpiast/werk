## What to build

The dev command runs the server under the hot reloader. A change to server code reloads the changed module and a chat turn that runs at the time continues to the end. Vite runs inside the server process and transforms the client. A client change that Vite cannot apply in place makes the server push "reload" on the live event channel, and the page reloads itself. The composer draft goes into session storage before the reload and comes back after it. One server runs per project: a second start waits up to 5 seconds for the lock, then refuses. A listen that finds the port in use retries every 250 ms, up to 20 times.

## Acceptance criteria

- [ ] An edit to a server module during a running fake-agent turn leaves the turn running to the end, and a new page opened during the turn sees it.
- [ ] A client edit that cannot apply in place reloads the page, and the composer draft is the same after the reload.
- [ ] A "changed" event refetches the graph and does not reload the page.
- [ ] A second server start on the same project prints that it waits for the live holder, then exits non-zero after about 5 seconds.
- [ ] A start whose port is held for a moment by an exiting process listens on a retry.
