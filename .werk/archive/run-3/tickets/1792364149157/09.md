## What to build

A chat pane sits beside the map. A person types in the composer and presses Enter. The request carries the text, any pasted images, the open card from the location hash, and the active conversation tab. The server hands it to a Claude Code child spoken to over stream-json, and the reply streams back over the live channel. The pane renders the person's messages and the agent's replies with the card-link rule.

Each turn starts with a line that names the card the person looks at. The agent's prompt states the card wording rules: a card describes its subject, not the session, and names no file, function, or line.

An agent reads a card's thread and writes a note to it from the command line. The server has a note route that appends a note and copies the `re #<id> "<title>": <text>` line to the clipboard; the browser never calls it.

A client change that forces a page reload keeps the composer draft.

## Acceptance criteria

- [ ] Enter in the composer sends the text, the pasted images, the open card, and the active tab. The fake agent receives all four.
- [ ] The reply from the fake agent appears in the pane while the turn runs, not only at the end.
- [ ] Each turn sent to the agent starts with the open card's id and title.
- [ ] The prompt given to the agent contains the card wording rules.
- [ ] A `#known-id` in a chat message renders as a link to the card.
- [ ] A note written from the command line appears in the card's thread, and the read command prints the thread.
- [ ] A "reload" event keeps the text typed in the composer.
