## What to build

A person runs the dev server on a project. A second start on the same project waits for the lock up to 5 seconds, then refuses with a message that names the live holder. When an old process is still releasing its socket, the new process retries the listen every 250 ms, up to 20 times.

The page listens on one live event channel (SSE). The server pushes "changed" when the log changes and "reload" when a client change cannot be applied in place. On "reload", the page reloads itself. Before the reload, the page saves any draft text it holds in session storage, and it restores the draft after the reload.

## Acceptance criteria

- [ ] A second server start on a project that has a live server prints a waiting line, waits up to 5 seconds, and then exits with a refusal.
- [ ] A second server start after the first server stops within the 5-second wait takes the lock and serves.
- [ ] A listen that fails with an address-in-use error retries every 250 ms, up to 20 times, and then fails with a clear message.
- [ ] An append to the log sends a "changed" event on the live channel.
- [ ] A client change that cannot be applied in place sends a "reload" event, and the open page reloads.
- [ ] A draft saved in session storage before a "reload" is back in place after the reload.
- [ ] All time limits are parameters, so a test runs them in milliseconds.
