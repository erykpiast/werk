## What to build

A build command takes one ticket and makes one worktree from a snapshot of the working tree. Each pass starts a fresh headless agent in the worktree. Its prompt holds the ticket brief and the last failure: the failed command and the end of its output, cut to about 4,000 characters. When the agent exits, the loop commits the worktree as "pass n".

The loop then runs the ticket's checks itself. A check is one command, and its exit code is the whole verdict. All green stops the loop. Red saves the failure and starts the next pass. The loop appends one line per pass to the run's record: check results, time, and cost.

The command is tested at its own command line, against a temporary git repository, with a scripted fake agent on the PATH that edits files the way a real agent does. Every time limit is a parameter.

## Acceptance criteria

- [ ] A ticket whose fake agent makes the checks green on pass 1 stops after one pass with one "pass 1" commit.
- [ ] A ticket that goes green on pass 2 has two pass commits, and the second agent's prompt holds the first failure, cut to about 4,000 characters.
- [ ] Each pass starts a new agent process. No agent lives longer than one pass.
- [ ] The run's record has one line per pass with check results, time, and cost.
- [ ] The loop's own check run decides the verdict, even when the agent claims the checks passed.
- [ ] The tests run the command against a temporary git repository with the fake agent, and assert only on exit code, branch, commits, and records.
