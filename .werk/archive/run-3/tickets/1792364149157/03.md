## What to build

An agent writes to the map only through the command line. Each verb appends one event at the end of the log: add a card, link two cards with a typed link, set a status, retitle, edit, remove, and restore. No event is ever rewritten or deleted.

The fold is a pure function from the event list to the map state: each card with its latest title, body, why, status, and links. The map view in the browser draws the fold as a refines tree, with a card view for the open card. The open card lives in the location hash.

No view edits a drawn card in place. A control in a view appends an event and every view redraws from the log. The first control is remove: a ✕ in the card view appends a remove event. A restore from the command line brings the card back.

## Acceptance criteria

- [ ] Each map verb on the command line appends exactly one event, at the end of the log, and changes no earlier line.
- [ ] After a retitle, the map shows only the new title, and the log still holds the old one.
- [ ] A removed card leaves the map, and a restore puts it back with its title, body, and links.
- [ ] The map view redraws from the log when a "changed" event arrives, with no page reload.
- [ ] The map view has no control that writes to a card's fields. The remove control appends a remove event through the server.
- [ ] The fold has unit tests, and its file is on the pure-file list of the coverage gate.
