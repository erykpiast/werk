## What to build

After a merge, a user path that must work does not work on the merged product. Make it work. Each path, word for word:

Scenario: A running background agent and a suggested next action
Given a person has a conversation in a tab
When the agent starts one background task and ends its turn
Then the pane shows a line under the chat log for the running background agent
And the tab counts as running
When the agent reports an empty list of background tasks
Then the line under the chat log is gone and the tab counts as idle
When the agent ends a reply with the line Next: say "merge it"
Then the pane shows a button labelled "merge it"
When the person clicks the button
Then "merge it" appears in the chat log as the person's message and the agent replies to it
And the "merge it" button is gone

## Before you build (#st-heldout-unbuilt-close)

Check two facts for each path. First, the path needs a capability that the main line does not provide and that another ticket, one that is not merged yet, builds. A capability is an operation of the command line, a screen or route, a field or kind of event in the log, or a behaviour of an agent. Second, the seam behind the path has unit tests that state its outcome, and they pass on the main line. When both facts hold for every path, change no code: the paths are not run until that ticket merges. When the second fact fails for a path, write the missing unit test at the seam and change nothing else for that path.

## Acceptance criteria

- [ ] A user can follow "A running background agent and a suggested next action" from start to end, or both facts above hold for it and a passing unit test at its seam states its outcome
