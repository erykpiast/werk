## What to build

After a merge, a user path that must work does not work on the merged product. Make it work. Each path, word for word:

Scenario: The model switch and clear context refuse during a turn and restart quietly when idle
Given a person has a conversation open with "Sonnet" in the model selector
And the context pie is blue before the first turn
When the person sends a message that makes a long turn
And the person picks "Opus" in the model selector while the turn runs
Then werk refuses the switch and the model selector still shows "Sonnet"
When the turn ends and the person picks "Sonnet with Opus advisor"
Then the model selector shows "Sonnet with Opus advisor"
And the pane shows no crash message
When the person clicks the context pie
Then a popover shows the fill percentage and a "Clear context" action
When the person clicks "Clear context"
Then the pane shows no crash message
And the next message the person sends gets an answer

## Before you build (#st-heldout-unbuilt-close)

Check two facts for each path. First, the path needs a capability that the main line does not provide and that another ticket, one that is not merged yet, builds. A capability is an operation of the command line, a screen or route, a field or kind of event in the log, or a behaviour of an agent. Second, the seam behind the path has unit tests that state its outcome, and they pass on the main line. When both facts hold for every path, change no code: the paths are not run until that ticket merges. When the second fact fails for a path, write the missing unit test at the seam and change nothing else for that path.

## Acceptance criteria

- [ ] A user can follow "The model switch and clear context refuse during a turn and restart quietly when idle" from start to end, or both facts above hold for it and a passing unit test at its seam states its outcome
