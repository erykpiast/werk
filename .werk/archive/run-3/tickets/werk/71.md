## What to build

Decision pass: a held-out step of werk/17 contradicts a decided card, so no code can satisfy both. Decide whether the card or the step is right, and propose the answer as a card. If the answer changes what the product does, build it.

Scenario: A person switches between the Map and Board tabs
Given the person has a card open in the map
And the Map tab is highlighted
When the person clicks the Board tab
Then the address is `/board`, the board shows, and the Board tab is highlighted
When the person reloads the page
Then the board still shows
When the person clicks the Map tab
Then the map shows the same card that was open before

It contradicts #werk-projects-names: The card says a project's name shows in the address, and #werk-projects-one-process puts every project in one server. So the Board address must carry the project, as /p/<project>/board does. The step requires the bare address /board, which leaves the project name out. #vi-routes lists /board, but that card names the view part of the address only. The rest of the step (Board tab highlight, reload keeps the board, Map tab returns to the same card) agrees with #vi-routes.
