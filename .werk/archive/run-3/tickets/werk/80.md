## What to build

After a merge, a user path that must work does not work on the merged product. Make it work. Each path, word for word:

Scenario: Tickets appear in their columns and a command line move redraws the board
Given a project whose board log holds tickets in blocked, ready, building, merging and done
When the person opens the board page
Then the board shows five columns in the order blocked, ready, building, merging, done
And each ticket card sits in the column its state names
And a ticket with two unfinished blockers shows a blocker count of 2
And a ticket that has been tried three times shows a retry count of 3
When the person moves a ready ticket into building from the command line
Then the board redraws without a page reload
And the ticket now shows in the building column and no longer in the ready column

## Before you build (#st-heldout-unbuilt-close)

Check two facts for each path. First, the path needs a capability that the main line does not provide and that another ticket, one that is not merged yet, builds. A capability is an operation of the command line, a screen or route, a field or kind of event in the log, or a behaviour of an agent. Second, the seam behind the path has unit tests that state its outcome, and they pass on the main line. When both facts hold for every path, change no code: the paths are not run until that ticket merges. When the second fact fails for a path, write the missing unit test at the seam and change nothing else for that path.

## Acceptance criteria

- [ ] A user can follow "Tickets appear in their columns and a command line move redraws the board" from start to end, or both facts above hold for it and a passing unit test at its seam states its outcome
