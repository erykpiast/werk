## What to build

After green checks, a grader agent reads the diff. It scores a delivery line per acceptance criterion, a contradiction line per decided card in the ticket's depends_on closure, and one scope line that fails for a behaviour no criterion and no story asks for. Each line gets a score from 1 to 5, where 3 passes, and the gap with the file, line or test that shows it. A card the grader leaves out scores 0. The first grade of a build names every gap; each later grade gets the earlier failed lines and fails a line only while its gap is open, or for a regression.

On a passing grade, five reviewer agents run at the same time, one per area (design, maintainability, tests, security and dependencies, performance), each with its own role name. A finding has a severity, a file and line, an impact and a fix. CRITICAL or HIGH fails the pass; MEDIUM, LOW and an unknown severity are recorded and do not block. A broken or silent grader or reviewer fails the pass as a failed step.

Grader and reviewers start with a fixed read-only tool list (read, search, find files, and git diff, log and show) and cannot ask for another tool.

On the last counted pass, a pass that fails only on small gaps (a contradiction line one point under a pass on a card the diff builds, that no person must settle) counts as green; if the review passes, the ticket goes to merging and a follow-up ticket is filed that cites the gaps' cards, quotes each gap and waits for the ticket.

## Acceptance criteria

- [ ] A grade of 2 on one criterion fails the pass, and the next builder prompt holds that gap.
- [ ] A second grade passes a line the first grade passed, even when the grader now names a new gap there.
- [ ] A HIGH finding from the security reviewer alone fails the pass and names the finding.
- [ ] The grader's launch record holds the read-only tool list and no write tool.
- [ ] Pass 5 failing only on a small gap moves the ticket to merging and files a follow-up that quotes the gap.
