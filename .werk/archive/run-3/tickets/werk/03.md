## What to build

One fake agent program answers under the name of the real agent. At launch it reads the script that the harness gave its temporary project. A script holds replies keyed by role name and an exit code. A reply is an ordered list of steps: an event printed as one line of the agent's output stream, a file edit written in the project, a pause, an ask, or a crash.

The fake reads the role name from its environment, so a test scripts one reply for the builder, another for the grader, and one per reviewer area. A chat role plays one reply per input message and waits until its input closes. Every other role reads the first message, plays one reply and exits with the script's code; a permission answer on its input belongs to the same reply.

An ask step prints the permission request and does not wait. The next steps play at once. The turn waits for open asks only before its final result. With no input channel the ask is denied at the end of the turn. A crash with an ask open exits with no tool result and no final result. Each pause adds a 20 ms margin.

An edit path that leads outside the project fails the step and writes nothing there. Each launch appends a record of its arguments and its role name in the project. With no script installed, the fake exits with an error at once.

## Acceptance criteria

- [ ] A builder reply and a grader reply are played by role name, and a reworded prompt changes nothing.
- [ ] A chat role answers two messages with two replies and exits when its input closes.
- [ ] A non-chat role with an ask in its reply exits after one reply with the script's exit code.
- [ ] An ask followed by a pause and a crash plays all steps before any answer, and the crash prints no final result.
- [ ] An edit to a path outside the project fails and leaves the outside file unchanged.
- [ ] Each launch leaves a record with its arguments and its role.
- [ ] The fake with no script exits non-zero at once.
