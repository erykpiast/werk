## What to build

A build runs in its own process, apart from the server. The server looks for dead builds when a build process it started exits and when the server starts: a build is dead when the board log has its start, no end, and its process is gone. For each one the server writes the end with died as the reason and starts a fresh pass of the same ticket from the last commit on its branch, with the death as the last failure. The fresh pass counts against the cap. A build whose process is alive is left alone, whoever started it.

## Acceptance criteria

- [ ] Killing a build process makes the server write the end with died and start the next pass from the branch's last commit.
- [ ] A build that died while the server was down is restarted when the server starts.
- [ ] A build that dies on its last allowed pass stops with died, and nothing more starts.
- [ ] A live build started by an earlier server is not touched.
