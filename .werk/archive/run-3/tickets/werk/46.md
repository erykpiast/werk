## What to build

A decided map card has a Build button. It is grey and names the blocking cards while the plan's scope holds an open or proto card. One press starts the plan and then the merge loop as one detached process with no time limit that outlives a server restart.

Every start of a run, from the map, the board or the command line, is refused while a run is in progress on the subtree or an ancestor, and names the blocking run. A subtree with unfinished work (ready, blocked, building or merging tickets) shows Resume, which restarts the merge loop, and Restart…, whose confirmation lists the builds it cancels and the tickets it archives before a new plan and run start. The command line's restart prints the same list and needs a confirmation. The map card and the plan card show the same state and the same disabled controls.

Below the columns, one plan card per subtree shows its state color: creating with the running step, building, done, or stopped with its reason; a plan whose process is gone without an end shows stopped. Its tickets link to it. A click opens the drawer with both writers' logs, the spec rendered in full, and the plan's tickets. While a plan runs, the root card on the map links to its plan card.

## Acceptance criteria

- [ ] A Build press on a scripted subtree leaves a plan card that goes from creating to building to done.
- [ ] A plan whose process is killed shows stopped, not pulsing.
- [ ] While a run is in progress on a parent, the child's controls are disabled and name the parent's run.
- [ ] A second press on a subtree with unfinished work offers Resume and Restart…, and starts nothing by itself.
- [ ] Restart lists what it cancels and archives before it does it.
