## What to build

After a merge, a user path that must work does not work on the merged product. Make it work. Each path, word for word:

Scenario: A pasted screenshot becomes a numbered image the agent reads by path
Given the person has the chat composer open on a project
When they paste a PNG screenshot into the composer
Then a chip appears above the composer showing a spinner
And the composer text contains "[Image #1]" at the caret
When the upload finishes
Then the chip shows a thumbnail of the screenshot and the token "[Image #1]"
When they type "Why is this red?" and press Enter
Then the message appears in the chat with the image shown under "[Image #1]"
And the agent's turn says "[Image #1]" is a path in the project's attachments folder
And the agent's turn tells it to open each image with a file read
And the agent's turn does not contain the image bytes

## Before you build (#st-heldout-unbuilt-close)

Check two facts for each path. First, the path needs a capability that the main line does not provide and that another ticket, one that is not merged yet, builds. A capability is an operation of the command line, a screen or route, a field or kind of event in the log, or a behaviour of an agent. Second, the seam behind the path has unit tests that state its outcome, and they pass on the main line. When both facts hold for every path, change no code: the paths are not run until that ticket merges. When the second fact fails for a path, write the missing unit test at the seam and change nothing else for that path.

## Acceptance criteria

- [ ] A user can follow "A pasted screenshot becomes a numbered image the agent reads by path" from start to end, or both facts above hold for it and a passing unit test at its seam states its outcome
