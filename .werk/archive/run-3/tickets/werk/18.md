## What to build

Each view has its own address: the map with a card, the map at the root, and the board. A card id in an address is URL-encoded, an unknown or removed id opens a page that says so, and the server answers every view address with the app. Back and Forward move between addresses.

Header row 1 holds the breadcrumbs from the root to the open card, one line high: the last two segments, a third when the pane is at least 700 px wide, an ellipsis for the rest, and a hover overlay with the whole path. Header row 2 holds the counts strip on the left (total, dots, rings, bare numbers with hover titles) and on the right the view tabs, then the search box.

The search box lists up to twelve cards, options, sources or excerpts whose id, title, reason or finding holds the text. A query with a leading # matches ids only, exact first, then prefix, then contains. Each row shows a status dot (stale red, postponed split grey), the title and the id. Arrows move, Enter opens, Escape clears.

## Acceptance criteria

- [ ] Opening a card changes the address, and Back returns to the previous card.
- [ ] An address with an unknown id shows that the card is not in the map.
- [ ] On a deep card the breadcrumbs stay one line, and hover shows the full path.
- [ ] Typing a card's exact id with # and pressing Enter opens that card.
- [ ] The Board tab opens the board address and Back returns to the map.
