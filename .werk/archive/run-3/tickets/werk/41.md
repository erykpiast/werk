## What to build

After each merge, the held-out set starts on that merge's commit in the background, and the queue takes the next ticket at once. An older run is not stopped by a newer merge; only the result on the main line's final tip opens G2. The set holds only the steps of the subtree's merged tickets; an archived ticket's steps leave with it and come back with a restore.

Before a run, each step whose source card changed since the step was written goes back to the step author, who rewrites or drops it. The binder reports a capability a step needs that the main line lacks: if another unmerged ticket owns it, the step is not run; if the step's own ticket owns it, the step is red. Before a red step files anything, the step author reads it against its source cards: a contradiction files a decision follow-up for the source ticket, which judges the step and the card by the easiest-to-undo rule, proposes a card and has the step rewritten. Otherwise the red steps are grouped by source ticket and file one follow-up per ticket, citing that ticket's cards; a step an open follow-up already carries files nothing. There is no limit on follow-ups per run.

A follow-up's merge gate also runs its own red steps on its temporary tree: all green or not run merges it; a red step sends it back with the cap applying. A follow-up whose every step needs a capability another ticket owns, and whose seams have passing unit tests, closes with no code change.

## Acceptance criteria

- [ ] The second ticket merges while the held-out run after the first merge is still going.
- [ ] Red steps from two source tickets file two follow-ups, each citing its own ticket's cards.
- [ ] A step of a ticket still building is not in the run after another ticket's merge.
- [ ] A step whose source card changed is rewritten before it can file anything.
- [ ] A follow-up whose step is still red on its tree does not merge.
- [ ] A step that needs an operation an unmerged ticket owns ends not run and files nothing.
