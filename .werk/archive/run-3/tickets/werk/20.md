## What to build

One server per machine holds one context per project: its map, conversations, agents, builds and lock. The project list is stored once per user, outside every project. A project is a folder with a git repository and a map, named by its folder name; a clash adds the parent folder in brackets.

Starting werk in a folder while a server runs adds the folder to the list, opens it in the browser and exits. A project stays on the list until the person removes it; a removal never touches its folder or its map, and asks for confirmation only when an agent turn runs. A moved folder shows as missing and does not open. In dev mode, werk's own checkout is always on the list, not stored, and cannot be removed. One hot reload reaches every project's context, and work in one project keeps running while the browser shows another.

Every API route names its project.

## Acceptance criteria

- [ ] A second start in another folder adds that project and exits, and both maps open from one server.
- [ ] Removing a project and adding its folder again shows the same map.
- [ ] A deleted folder shows as missing and does not open.
- [ ] Two folders named api get distinct names.
- [ ] In dev mode the checkout is on the list after a restart and cannot be removed.
