## What to build

After a merge, a user path that must work does not work on the merged product. Make it work. Each path, word for word:

Scenario: A person opens a deep card and follows the breadcrumbs back
Given a map where a card sits four levels below #root
And the left pane is narrower than 700px
When the person opens the home view and opens the deep card from the map
Then the header shows the path on one line, with a `…`, then the parent card, then the open card in bold
And the segments are separated by `›`
When the person hovers over the path
Then an overlay shows the full path from Home to the open card
When the person clicks the parent card in the path
Then the map shows the parent card, and the path ends with the parent card in bold

## Before you build (#st-heldout-unbuilt-close)

Check two facts for each path. First, the path needs a capability that the main line does not provide and that another ticket, one that is not merged yet, builds. A capability is an operation of the command line, a screen or route, a field or kind of event in the log, or a behaviour of an agent. Second, the seam behind the path has unit tests that state its outcome, and they pass on the main line. When both facts hold for every path, change no code: the paths are not run until that ticket merges. When the second fact fails for a path, write the missing unit test at the seam and change nothing else for that path.

## Acceptance criteria

- [ ] A user can follow "A person opens a deep card and follows the breadcrumbs back" from start to end, or both facts above hold for it and a passing unit test at its seam states its outcome
