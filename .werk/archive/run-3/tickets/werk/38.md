## What to build

The run verb starts the merge loop over one subtree's tickets in the project's target repository; running it again resumes. Every start first writes the feature tier event to the board log. No operation sets or raises a tier, so every gate waits for a person.

The loop builds each ready ticket whose blockers are merged, then takes finished tickets one at a time. It merges the ticket's branch onto the main line in a detached worktree and runs the ticket's checks there. Red checks send the ticket back to building with the failure. Green moves the main line only from the value it had when the merge started; a checkout of the main line moves with a fast-forward, and a checkout whose local changes block it stops the loop with nothing moved.

When git cannot merge, the next pass starts from the ticket's own branch with the main line merged in, gets the conflicted files and output, does not count against the cap, and a green result goes to the front of the queue. Ten conflicts in a row make the ticket stuck. A stuck ticket moves to blocked with the reason, and the tickets that need it stay blocked behind it; the loop goes on with the rest and ends only when nothing can build or merge, reporting each stuck ticket. A loop that stops moves every ticket it left in building or merging back to ready with the stop reason.

The gate verb shows G2 for a subtree as waiting once every ticket is merged, and passes it only with the person's statement.

## Acceptance criteria

- [ ] A subtree of two independent scripted tickets ends with both merged on the main line and both in done.
- [ ] The first board event of a run is the feature tier event.
- [ ] A red merge check sends the ticket back to building, and nothing of it reaches the main line.
- [ ] A conflict pass does not raise the counted passes, and its green result merges next.
- [ ] A ticket stuck at its cap parks only itself and its dependents; an independent ticket still merges.
- [ ] The gate verb refuses to pass G2 without the person's statement.
