## What to build

The client has its own folder beside the server code. In dev, Vite runs in middleware mode inside the werk server on the same port; the build writes the client to its own output folder, which the server serves. React roots mount where state lives, and every control comes from shadcn/ui components. The screen has two panes: a left pane with a sticky two-row header and a body that shows one view, and a right pane slot.

Each page holds one live channel. The server watches the log directory before it accepts a connection. When the log grows it sends a bare map signal; every page then reads the shape again. On each connect the page fetches the whole map. A client change that Vite cannot apply in place sends a reload signal; the page stashes the composer draft per tab and restores it. `make dev` starts this.

The browser harness runs Playwright against a real server on a copy of a fixture project, with the fake agent first on the search list; the server refuses to start when it is not. Tests assert on structure and write a screenshot as evidence. Each unit test worker registers one DOM before any test file and puts back the runtime network, stream and timer globals.

## Acceptance criteria

- [ ] `make e2e` opens the root card's title in the left pane of a real server.
- [ ] A card added from the command line appears in an open page with no reload.
- [ ] A card added while the server was stopped shows after the server starts and the page reconnects.
- [ ] A client edit that cannot apply in place reloads the page and keeps a typed draft.
- [ ] The browser server refuses to start when the fake agent is not first.
- [ ] A component test and a server test that calls the network both pass in one worker.
