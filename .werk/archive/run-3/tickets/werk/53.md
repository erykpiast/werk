## What to build

After a merge, a user path that must work does not work on the merged product. Make it work. Each path, word for word:

Scenario: The agent runs the unit tests and then the coverage gate
Given the werk repository with its first pure helper and that helper's own test file
When the agent runs `make test`
Then the unit tests pass
And the run reports its results without a coverage check
When the agent runs `make test-coverage`
Then the output shows one line for each file on the pure-file list with its line percentage
And the coverage command passes
When the agent deletes the own test file of a file on the pure-file list
And the agent runs `make test-coverage` again
Then the output shows 0% for that file
And the coverage command fails and names the missing test file
But `make test` still passes without a coverage failure

## Before you build (#st-heldout-unbuilt-close)

Check two facts for each path. First, the path needs a capability that the main line does not provide and that another ticket, one that is not merged yet, builds. A capability is an operation of the command line, a screen or route, a field or kind of event in the log, or a behaviour of an agent. Second, the seam behind the path has unit tests that state its outcome, and they pass on the main line. When both facts hold for every path, change no code: the paths are not run until that ticket merges. When the second fact fails for a path, write the missing unit test at the seam and change nothing else for that path.

## Acceptance criteria

- [ ] A user can follow "The agent runs the unit tests and then the coverage gate" from start to end, or both facts above hold for it and a passing unit test at its seam states its outcome

- `make lint`
- `make typecheck`
