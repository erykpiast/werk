## What to build

After the grader passes, the builder loop runs a review step. Five reviewer agents start at the same time, each with a fresh context and one area of #lp-prod-review's rubric: design, maintainability, tests, security and dependencies, performance. Each gets the diff and reports only on the diff and the code it directly affects.

Each finding has a severity, a file and line, the impact, and a fix. A CRITICAL or HIGH finding fails the pass, and every such finding goes into the next builder pass. MEDIUM and LOW findings do not block. The loop records them for the trend.

A new pass after a fail runs the checks, the grader, and all five reviewers again.

## Acceptance criteria

- [ ] Five reviewer processes run at the same time, each with one area in its prompt.
- [ ] A fake reviewer with one HIGH finding fails the pass. The next builder pass gets the finding.
- [ ] Only MEDIUM and LOW findings: the build ends green, and the findings are in the ticket's record.
- [ ] A finding on a file the diff does not touch is dropped and logged as dropped.
- [ ] Every finding is one event in the log.
