## What to build

`werk build <ticket-file>` builds one ticket in its own worktree. It reads the ticket: what to build, acceptance criteria, stories, cites, and checks. It collects the decided cards in the depends_on closure of the cited cards, and the spec's text for each listed story.

Each pass starts a fresh agent. The agent gets the brief, the cards, the stories, and the last failure, and nothing else. When the agent exits, the loop commits the worktree as one pass and runs the ticket's checks itself. Green: the ticket is done. Red: the failed command and the end of its output go into the next pass. At the cap of 5 passes the loop stops and keeps the branch.

Every state change goes to the run's append-only event log: pass start, pass end, each check result, done, capped.

This ticket has only the check step. The grader and the review come in later tickets, behind a step list the loop runs in order, so each one adds a step and does not change the loop.

Start from the `werk loop` prototype. Keep its long mode for the #lp-stateless comparison.

## Acceptance criteria

- [ ] With a fake agent that fixes the code on pass 2, the build ends green after 2 passes, with 2 commits on the branch.
- [ ] Pass 2's prompt holds pass 1's failed command and output tail, and does not hold pass 1's prompt or transcript.
- [ ] The prompt holds the text of each listed story and each card in the closure.
- [ ] A fake agent that never fixes the code stops at 5 passes. The branch stays, and the exit code is non-zero.
- [ ] A fake agent that prints "all checks pass" but leaves a red check does not end the build.
- [ ] The event log has one event per state change above, in order.
