## What to build

The ticket's summary record gets the secondary signals from #lp-trend-secondary:

- The runtime of each check, summed over the passes.
- The flaky checks. A check is flaky when it fails, and a run of the same check on the same commit then passes. The loop re-runs a red check once on the same commit to find out.
- The count of MEDIUM and LOW review findings.
- A drift score between the project's agent docs and its code. A judgement agent reads the agent docs and the diff and returns a score and the drifted lines.

## Acceptance criteria

- [ ] A check that fails once and passes on the re-run is recorded as flaky, and the pass is not failed by it.
- [ ] A check that fails twice on the same commit fails the pass, and is not recorded as flaky.
- [ ] The summary has check runtime, flaky checks, MEDIUM and LOW counts, and the drift score.
- [ ] Bad output from the drift judgement records no score and logs the error. It does not fail the ticket.
