## What to build

`werk run <ticket-dir>` builds every ticket in the directory and merges them into one run branch.

1. It orders the tickets by blocked_by. A ticket starts only when every ticket that blocks it is merged.
2. It builds each ticket with the builder loop, one ticket at a time (#st-build-serial).
3. A finished ticket enters the merge queue. The coordinator makes a temporary tree: the run's tree plus the ticket's branch. It runs the checks there.
4. Green: the temporary tree becomes the run's tree. Red: nothing merges. The ticket goes back to its builder loop with the failure as its next pass's input. The ticket's own retry cap still applies.

A merge conflict counts as a red merge check, with the conflict as the failure.

Every merge, red merge check, and return to the builder goes to the event log.

## Acceptance criteria

- [ ] Three fixture tickets with blockers 01 ← 02 ← 03 build and merge in that order.
- [ ] Two tickets that are green alone and break each other when merged: the second does not merge, and its next pass gets the merge failure.
- [ ] The run's branch is green after every merge.
- [ ] A ticket that reaches its cap stops the run, and the run's branch keeps what merged before it.
- [ ] A textual merge conflict sends the ticket back with the conflict in its input.
