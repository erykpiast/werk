## What to build

After each merge, the coordinator runs the held-out set on the run's tree. The held-out set lives outside every builder's worktree, so no builder can read it. Each held-out step has a text, in user terms, and a test bound to it.

A red step files a follow-up ticket in the run's ticket directory. The merge stands, and build goes on. The follow-up's brief holds the failed step's text word for word. It does not hold the test code or the other steps. The follow-up is a new ticket with a new retry cap.

The run ends when every ticket, follow-ups included, is merged and every held-out step passes on the final tree. There is no limit on the number of follow-ups.

## Acceptance criteria

- [ ] A builder's worktree has no copy of the held-out set, and its prompt has no path to it.
- [ ] A red held-out step after a merge files one follow-up ticket, and the merge stays on the run's branch.
- [ ] The follow-up's prompt has the step text and no test code.
- [ ] A run with a red held-out step does not end until a follow-up makes it green.
- [ ] A run with no held-out set ends when every ticket is merged.
- [ ] Each held-out result and each follow-up is one event in the log.
