## What to build

`werk trend` reads every ticket summary of the project, in build order, and prints each metric from #lp-trend-primary and #lp-trend-secondary. The effort metrics are divided by the ticket's story count. A ticket with an empty stories list counts as 1.

For each metric it compares two windows: the base is the first 10 tickets, the current window is the last 10. A metric 20% or more above the base raises an alert. With fewer than 11 tickets, no alert is possible.

An alert is information only. It is printed and written to the event log. It never blocks a merge and never stops a build.

## Acceptance criteria

- [ ] A ticket with 3 stories and 6 passes reports 2 passes per story.
- [ ] A ticket with no stories divides by 1.
- [ ] 20 fixture summaries with the last 10 at +25% passes per story raise one alert for that metric.
- [ ] The same fixtures at +15% raise no alert.
- [ ] 10 fixture summaries raise no alert.
- [ ] A build running while an alert exists ends the same way as with no alert.
